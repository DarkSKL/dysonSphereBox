# 界面视觉规范

## 适用范围与设计定位

用于前端页面、组件、布局、字体、配色及交互状态的开发和审查。与 `project-standards.md` 配合使用；此文件细化视觉规则，不改变业务架构。用户在当前任务中的明确要求优先。

产品面向戴森球计划玩家和联机服务器维护者，主要操作是模组安装、资源管理、开服、日志诊断和设置。功能页面保持紧凑、清晰、易于扫描；首页保留戴森球场景和品牌特色。现有视觉方向为深空科技主题，日间与夜间有各自的配色逻辑。

实现前先检查以下入口，文档中的路径均相对应用根目录：

| 入口 | 职责 |
| --- | --- |
| `frontend/src/style.scss` | 本地字体声明、字体与色彩 token、全局基础样式 |
| `frontend/src/App.vue` | Naive UI 主题与字体覆盖 |
| `frontend/tailwind.config.cjs` | Tailwind 字体工具类和扫描配置 |
| `frontend/src/composables/useThemeMode.ts` | 日夜模式、持久化及 `html[data-theme]` |
| `frontend/src/packages/dyson-sphere/internal/palette.ts` | 戴森球场景的日夜调色板 |

色值与字体资产以当前源码为准。调整视觉规则时同步更新相关入口和本文，不为同一用途创建另一套局部主题。

## 字体分工

| 用途 | 字体 | Token / 用法 | 典型内容 |
| --- | --- | --- | --- |
| 中文界面 | 思源黑体 | `--ds-font-ui`、`font-sans`、默认继承 | 导航、标题、标签、按钮、正文、提示和空状态 |
| 特色数字与英文 | Oxanium | `--ds-font-display`、`font-display`、`type-display` | 英文品牌、特色英文标识、进度百分比、数量、网络速率及图表刻度 |
| 日志与技术信息 | JetBrains Mono | `--ds-font-mono`、`font-mono`、`type-mono` | 日志、代码、JSON、路径、URL、版本号、端口、PID、协议、蓝图编码 |

按内容用途选择字体。中文句子中出现英文或数字不需要逐字替换；普通文案继续使用思源黑体。动态版本号、文件名等属于技术信息，即使含数字，也使用 JetBrains Mono。

英文品牌和数字容器使用 Oxanium 优先的字体栈，中文回退到思源黑体。JetBrains Mono 不含中文，其字体栈也须包含思源黑体等中文回退，保证混合日志和中文路径可读。不要用 Nunito 或系统默认字体重新覆盖这些用途。

### 资产与加载

当前资产位于 `frontend/src/assets/fonts/`：

- 思源黑体：`SourceHanSansHWSC/OTF/SimplifiedChineseHW/SourceHanSansHWSC-Regular.otf` 和 `SourceHanSansHWSC-Bold.otf`。当前资源为 HWSC 版本，CSS 注册名称为 `Source Han Sans SC`。
- Oxanium：`Oxanium/Oxanium-VariableFont_wght.ttf`，字重范围 `200 800`。
- JetBrains Mono：`JetBrainsMono/fonts/variable/JetBrainsMono[wght].ttf`，字重范围 `100 800`；目录也包含可按需使用的 WOFF2 静态字重。

统一在 `style.scss` 声明 `@font-face`，使用相对资源路径交给 Vite 打包，并设置 `font-display: swap`。无需联网加载或要求用户安装字体。保留字体已有的许可证文件。

思源黑体现有静态字重为 `400` 和 `700`，声明须与文件一致；不要将静态文件声称为可变字体。页面的其他字重由浏览器匹配现有文件。需要额外字重或斜体时先检查资产，不重复导入整套字体。

思源黑体的两个 OTF 文件合计约 32 MiB，应检查打包体积；不要默认预加载所有字重。后续压缩或子集化需保留许可和实际字符覆盖，特别是中文日志与用户文件名。

### 组件接入

- 全局 `html`、`body` 与 Naive UI `common.fontFamily` 使用中文界面字体。
- Naive UI `common.fontFamilyMono` 使用技术字体栈，覆盖 `n-code` 等组件；不要用通用省略文本、弹窗或卡片选择器强制改为等宽字体。
- 技术输入框在 `n-input` 上加 `type-mono`，全局规则命中实际 input/textarea 元素；控件中的中文标签和说明保持界面字体。
- `<pre>`、`<code>`、`<kbd>`、`<samp>` 使用技术字体。日志和编码关闭连字，避免符号组合改变原始文本的外观。
- 动态数值可用 `font-variant-numeric: tabular-nums` 稳定宽度。给频繁更新的数值预留空间，避免挤压同一行的按钮或状态。
- ECharts 等 Canvas 文本不能直接使用 CSS `var(...)`。读取 token 的实际字体栈或使用明确的主题字体值；字体异步加载后更新图表，避免刻度持续使用回退字体。
- 第三方蓝图预览保留已有的主题隔离、样式清理和生命周期处理，不直接修改其打包代码来实现全局字体适配。

## 配色与主题

### 日间与夜间

以下为当前基准，维护时与 `style.scss`、Naive UI 覆盖和场景调色板核对：

| 语义 Token | 日间 | 夜间 |
| --- | --- | --- |
| `--ds-bg-app` | `#e6e6e6` | `#020409` |
| `--ds-bg-shell` | `#ebebeb` | `#03060d` |
| `--ds-bg-panel` | `#f3f3f3` | `#0a0f1a` |
| `--ds-bg-panel-elevated` | `#f8f8f8` | `#0f1624` |
| `--ds-text-primary` | `#18181a` | `#eceef8` |
| `--ds-brand` | `#1c1c1e` | `#4cc2ff` |
| `--ds-success` | `#4a7560` | `#3ee0b0` |
| `--ds-warning` | `#94682a` | `#ffc15a` |
| `--ds-error` | `#a8434a` | `#ff6b7f` |
| `--ds-info` | `#5a5a5e` | `#6aa8ff` |

日间的背景、文字、边框和普通主操作以白灰黑中性色为主，不将夜间蓝色强调直接带入日间。成功、警告、错误等状态保留低饱和语义色。

夜间使用深空背景、明亮文字和蓝色主强调。青绿用于成功或资源启用等语义状态。星云、光晕和现有场景渐变归属于场景与少量选中指示，不铺满功能页面。

资源启用状态使用单独的 `--ds-res-on*` 系列：日间以青绿为强调，夜间使用现有蓝绿能量环。关闭状态使用 `--ds-res-off*`。这套资源状态不能替代全局成功、错误和警告 token。

存档卡片使用 `--ds-save-accent` 和 `--ds-save-ring-*` 蓝色描边，按产品要求在日夜主题均保持蓝色，日间降低亮度。描边复用资源卡片流动节奏，减少动态效果时静止；蓝色仅标识 .dsv 存档，不表示资源启用状态。

### Token 使用

- 业务组件通过 `--ds-bg-*`、`--ds-text-*`、`--ds-border-*`、`--ds-brand*` 和状态 token 配色，复用现有语义，不在每个页面硬编码一套日夜色值。
- 背景、正文、次要文字、弱提示、边框各自使用对应层级。弱提示色不用于重要操作或必须阅读的错误内容。
- 状态提示同时提供文字或图标，不能只靠红绿颜色区别；禁用、加载、空状态与失败状态需要可辨认。
- 主按钮文字使用 `--ds-brand-contrast-text` 对应的主题值，检查正常、悬停、按下和聚焦状态。
- 主题切换由 `useThemeMode.ts` 管理；不要由页面独立修改全局 theme 属性或持久化键。

## UI 结构与控件

功能页面使用平面分区、工具栏、分隔线、列表、表格和必要的分栏，优先保障重复操作效率。卡片只用于独立资源条目、弹窗或真正需要边框的工具；不将整页分区包装成浮动卡片，不嵌套卡片。

- 常规控件和面板圆角以 `4px` 为基准，使用细边框和少量阴影。状态点、头像等有明确形状需求的元素沿用已有样式。
- 使用已安装的 Naive UI 控件与 `@lucide/vue` 图标。图标操作提供 tooltip 和可访问名称；数值用输入框、步进器或滑块，二元状态用 checkbox/toggle，选项集用 select/menu。
- 中文功能页标题与工具栏保持紧凑，使用当前页面的字号层级。首页场景标题可以较大，不把首页尺度带入设置项或弹窗。
- 不按视口宽度缩放文字。新增字体样式保持 `letter-spacing: 0`；调整既有品牌字距时检查实际宽度和窄窗口布局。
- 功能页留白优先使用 `--ds-page-padding-*` 和已有页面结构。固定尺寸工具、图标按钮和动态计数保持稳定尺寸。
- 长路径、日志、URL 和编码允许合理换行或滚动；单行省略时提供可查看完整内容的入口。不能因字体变化让文本覆盖邻近内容。
- 缓存页面、浮层、提示消息和错误状态也要跟随主题与字体，不只验证初始页面。修改 UI 时保留 Driver.js 教程选择器与目标的一致性。

## 验证要求

字体与视觉变更完成后，在 `frontend` 运行 `npm run build`，检查类型、资源路径和打包字体；构建通过不等同于行为验证。

使用现有 Wails 开发服务验证实际页面，检查：

- 浏览器 `document.fonts` 中对应字体加载成功；computed style 与内容用途一致，英文和中文回退均可读。
- 日间、夜间以及常见宽窗口和窄窗口下，标题、指标、输入框、弹窗和日志不重叠、不意外产生横向溢出。
- 真实技术输入和代码组件使用 JetBrains Mono，空状态及普通提示仍使用思源黑体。
- Canvas 图表在字体加载后显示正确刻度，关键数字更新时布局稳定。
- 构建生成文件没有引入无关修改；不要手工编辑 Wails 绑定和自动生成的组件、路由声明。

仅涉及规范文档时检查引用链接、路径和规则与当前实现一致，无需为 Markdown 变更运行应用构建。
