# 戴森球计划蓝图解析方案

本文档汇总《戴森球计划》蓝图字符串的解析逻辑，目标是把一串 `BLUEPRINT:` 编码解析为可读 JSON，包括蓝图元信息、区域信息、建筑列表、坐标、连接关系和建筑参数。

## 1. 总体格式

蓝图字符串外层格式大致如下：

```text
BLUEPRINT:<meta fields>"<base64(gzip(binary))>"<MD5F checksum>
```

其中：

- `BLUEPRINT:` 是固定前缀。
- 第一个双引号前是逗号分隔的元信息。
- 双引号中间是 `gzip` 压缩后的二进制数据，再经过 `Base64` 编码。
- 最后 32 位十六进制字符串是游戏使用的 `MD5F` 校验，不是标准 MD5。

解析时建议先只做结构校验、Base64 解码和 gzip 解压；如果要重新生成可导入游戏的蓝图，再实现 `MD5F`。

## 2. 外层元信息解析

处理步骤：

1. 校验字符串以 `BLUEPRINT:` 开头。
2. 查找第一个 `"`，之前为元信息区。
3. 查找最后一个 `"`，中间为 Base64 payload，之后为 checksum。
4. 元信息区去掉 `BLUEPRINT:` 后按 `,` 分割。
5. 对标题、描述等文本字段执行 URL percent decode。

常见字段含义可按下面方式理解：

```text
0  蓝图外层版本 / 类型
1  图标布局
2  图标 1
3  图标 2
4  图标 3
5  图标 4
6  图标 5
7  保留字段
8  创建时间 .NET ticks
9  游戏版本号
10 短标题 / 短描述
11 保留字段
12 保留字段
13 保留字段
14 长标题 / 长描述
```

时间戳是 .NET ticks，从公元 1 年 1 月 1 日开始，每 tick 为 100ns。换算逻辑：

```ts
const unixMs = Math.floor((ticks - 621355968000000000n) / 10000n);
const date = new Date(Number(unixMs));
```

## 3. 二进制读取规则

二进制数据使用小端序。建议实现一个 `BinaryReader`，提供：

```ts
readInt8()
readUInt8()
readInt16()
readUInt16()
readInt32()
readFloat32()
readBytes(length)
```

所有读取都应该检查越界，方便发现字段错位。

## 4. 二进制头部结构

解压后的 binary 先读取蓝图头：

```text
version            int32
cursorOffsetX      int32
cursorOffsetY      int32
cursorTargetArea   int32
dragBoxSizeX       int32
dragBoxSizeY       int32
primaryAreaIdx     int32
areaCount          uint8
```

然后读取 `areaCount` 个区域：

```text
index               int8
parentIndex         int8
tropicAnchor        int16
areaSegments        int16
anchorLocalOffsetX  int16
anchorLocalOffsetY  int16
width               int16
height              int16
```

然后读取：

```text
buildingCount       int32
```

## 5. 建筑记录结构

蓝图建筑记录需要按记录首个 `int32` 分支解析。官方游戏结构在较新版本中会写入负数格式前缀，旧版结构则没有独立前缀，首个 `int32` 直接就是建筑 `index`。因此解析时必须先读取：

```text
firstWord           int32
```

如果 `firstWord < -100`，说明是新版建筑记录，`firstWord` 作为 `num` 诊断字段保存，后续继续读取：

```text
index               int32
itemId              int16
modelIndex          int16
areaIndex           int8
localOffsetX        float32
localOffsetY        float32
localOffsetZ        float32
yaw                 float32
```

对传送带类建筑，`2000 < itemId < 2020`，继续读取：

```text
tilt                float32
```

对分拣器类建筑，`2010 < itemId < 2020`，还会继续读取第二端坐标与角度：

```text
pitch               float32
localOffsetX2       float32
localOffsetY2       float32
localOffsetZ2       float32
yaw2                float32
tilt2               float32
pitch2              float32
```

之后读取通用字段：

```text
outputObjIdx        int32
inputObjIdx         int32
outputToSlot        int8
inputFromSlot       int8
outputFromSlot      int8
inputToSlot         int8
outputOffset        int8
inputOffset         int8
recipeId            int16
filterId            int16
parameterCount      int16
parameters          int32[parameterCount]
contentLength       int32
content             byte[contentLength], UTF-8
```

如果 `firstWord == -100`，说明是中间版建筑记录：它带负数格式前缀，但字段主体仍接近旧版坐标顺序。字段顺序为：

```text
num                 int32  // 已由 firstWord 读取，值通常为 -100
index               int32
areaIndex           int8
localOffsetX        float32
localOffsetY        float32
localOffsetZ        float32
localOffsetX2       float32
localOffsetY2       float32
localOffsetZ2       float32
yaw                 float32
yaw2                float32
reserved            int32
itemId              int16
modelIndex          int16
outputObjIdx        int32
inputObjIdx         int32
outputToSlot        int8
inputFromSlot       int8
outputFromSlot      int8
inputToSlot         int8
outputOffset        int8
inputOffset         int8
recipeId            int16
filterId            int16
parameterCount      int16
parameters          int32[parameterCount]
```

如果 `firstWord > -100`，说明是旧版无前缀建筑记录，`firstWord` 应作为 `index` 使用，不能报“旧版建筑记录前缀不支持”。旧版字段顺序为：

```text
index               int32  // 已由 firstWord 读取
areaIndex           int8
localOffsetX        float32
localOffsetY        float32
localOffsetZ        float32
localOffsetX2       float32
localOffsetY2       float32
localOffsetZ2       float32
yaw                 float32
yaw2                float32
itemId              int16
modelIndex          int16
outputObjIdx        int32
inputObjIdx         int32
outputToSlot        int8
inputFromSlot       int8
outputFromSlot      int8
inputToSlot         int8
outputOffset        int8
inputOffset         int8
recipeId            int16
filterId            int16
parameterCount      int16
parameters          int32[parameterCount]
```

注意：

- `outputObjIdx` 和 `inputObjIdx` 是建筑之间的连接索引，`-1` 表示无连接。
- 传送带的 `outputObjIdx` 常用于下一段传送带或连接建筑。
- 分流器 `itemId` 通常为 `2020`，参数数组常见长度为 6。
- `content` 多数建筑为空；信标、文本类或新版字段可能使用它。旧版记录没有 `contentLength/content` 字段，解析时不要额外读取。

## 8. TypeScript 解析流程伪代码

```ts
export function decodeBlueprint(input: string): DecodedBlueprint {
  if (!input.startsWith("BLUEPRINT:")) {
    throw new Error("Invalid blueprint prefix");
  }

  const firstQuote = input.indexOf('"');
  const lastQuote = input.lastIndexOf('"');
  if (firstQuote < 0 || lastQuote <= firstQuote) {
    throw new Error("Invalid blueprint quotes");
  }

  const metaPart = input.slice(0, firstQuote);
  const payloadBase64 = input.slice(firstQuote + 1, lastQuote);
  const checksum = input.slice(lastQuote + 1);

  const rawFields = metaPart
    .slice("BLUEPRINT:".length)
    .split(",")
    .map((field) => decodeURIComponent(field));

  const compressed = Buffer.from(payloadBase64, "base64");
  const binary = gunzipSync(compressed);
  const reader = new BinaryReader(binary);

  const version = reader.readInt32();
  const cursorOffset = { x: reader.readInt32(), y: reader.readInt32() };
  const cursorTargetArea = reader.readInt32();
  const dragBoxSize = { x: reader.readInt32(), y: reader.readInt32() };
  const primaryAreaIdx = reader.readInt32();

  const areaCount = reader.readUInt8();
  const areas = Array.from({ length: areaCount }, () => readArea(reader));

  const buildingCount = reader.readInt32();
  const buildings = Array.from({ length: buildingCount }, () =>
    readBuilding(reader),
  );

  if (!reader.isEnd()) {
    throw new Error(`Trailing bytes: ${reader.remaining}`);
  }

  return {
    meta: {
      rawFields,
      title: rawFields[10],
      description: rawFields[14],
      gameVersion: rawFields[9],
      createdAt: ticksToDate(rawFields[8]),
      checksum,
    },
    binary: {
      version,
      cursorOffset,
      cursorTargetArea,
      dragBoxSize,
      primaryAreaIdx,
      areas,
      buildings,
    },
  };
}
```

## 9. 校验与测试建议

至少准备三类测试数据：

1. 只有传送带和分流器的简单蓝图。
2. 带分拣器的蓝图，用于验证第二端坐标和 pitch/yaw2/tilt2。
3. 带配方、过滤器、参数或文本内容的蓝图，用于验证 `recipeId`、`filterId`、`parameters`、`content`。

解析成功条件：

- gzip 解压成功。
- `buildingCount` 与实际读取出的建筑数量一致。
- 最终 reader offset 等于 binary length。
- 建筑 `itemId`、坐标和连接关系符合游戏中观察到的布局。

## 10. 重新编码注意事项

如果不仅要解析，还要修改后重新生成蓝图，需要按逆序执行：

1. 按同样字段顺序写入小端二进制。
2. gzip 压缩。
3. Base64 编码。
4. 拼接外层元信息。
5. 计算游戏专用 `MD5F` 并追加。

其中 `MD5F` 不是标准 MD5，必须单独实现或引用可靠的社区实现；否则游戏会拒绝导入。
