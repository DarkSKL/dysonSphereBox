# 候选并发与可视化验证记录

日期：2026-11-07。状态：核心实现已完成，完整验收尚未完成。以下区分源码检查、离线行为检查、浏览器检查与尚未执行的桌面检查。

## 已落地行为

- 一个生成任务独占准入；任务内部最多四个 worker，固定波次，候选结束后按原序号归约。`candidateConcurrency` 可指定 1、2、4（或 3），零为自动，不修改全局 GOMAXPROCS。
- 四个公开模式的主要搜索入口均已接入。主候选全部失败才进入兼容组；配送策略的条件扩展仍由原有条件决定，失败预算和可行性比较规则保持原语义。
- Builder、Notifier、预览身份与候选性能阶段独立。只读输入共享，模式比较器与已获选指标在波次边界读取；路由、碰撞与候选计数归并到请求统计。
- v4 在计算前声明全部已确定候选。配送与密铺物流塔预先声明已知策略集合；条件回退组在实际启用时追加。每个候选使用稳定身份、序号和独立对象空间。
- 前端以一个 WebGL renderer 和共享模型资源显示全部候选，不以四个平台或 12000 个建筑截断多候选场景。平台分开排布，失败后保留空位，不重新编号。
- 每个平台有独立视觉时钟和队列，默认约 60 操作/视觉秒；积压不会自动跳过旧动画。失败候选播到自己的结束节点后独立下坠，第一次非空画面至少保留约 1.2 个视觉秒。最后只保留获选平台并平滑归中。
- 正式快照按版本和分块组装，校验对象唯一性及建筑总数，再等待旧过程播放完毕后统一切换正式姿态。获选 ID 必须与成功返回值一致才结算。
- 渲染队列积压约 20000 项时，未消费过程留在后端日志，稍后继续按页读取。日志最近两次任务、每任务上限 64 MiB、十分钟有效；正常退出时删除。过期、写入失败及缺块均明确提示，不假装完整回放。
- 新任务和组件卸载会停止旧观察者，包括正式请求已返回、仍在读取演示尾部的观察者。工作区按自己的任务 ID 分流，不接收其他工作区的生成事件。
- 暂停不暂停计算；跳过会持续作用于本次演示后来补发的尾部，下一次任务重置。GPU 上下文恢复仍使用当前 CPU 场景，不恢复旧任务对象。

## 实施差异

原设计允许以当前快照修复断流，实施改用完整事件日志补发：它不仅修复当前状态，还保留暂停期间的装配历史，更符合“计算已结束但演示仍继续”的要求。最终正式快照仍独立分块并原子组装。实际接口为 `ReadGenerationProgress(taskId, afterSequence)`。

建筑实例池按模型共享，通过实例矩阵叠加各平台的位移；每个平台独占地板、队列、视觉状态和范围。这样保留完整模型，同时避免每个平台重复创建同一材质、贴图和 draw call。候选退场释放自己的实例槽，共享资产留给其他平台。

控制器实际接口为 `beginCandidate`、`enqueue`、`finishCandidate`、`finalizeSearch`、`failSearch`、`reset`，没有额外引入同义的 beginSearch/clearSearch。

## 离线行为证据

临时 Go 验证程序直接调用真实 quant 与 build 引擎，检查：事件全局顺序、候选内顺序、候选开始/结束配对、对象操作合法性、正式快照数量、逐页日志与原始事件逐项相等。对成功输出严格解码后比较建筑和区域 JSON 的 SHA-256，忽略封装时间等非布局元数据。

| 输入 | 覆盖 | 结果 |
| --- | --- | --- |
| 电磁矩阵 60/min，平面，无喷涂 | 四模式×普通/密铺，串行与四 worker；直连带另查二 worker | 获选、建筑、区域一致 |
| 电磁矩阵 600/min，自动球面布局 | 四模式×普通/密铺×1/2/4 worker | 全部成功，获选、建筑、区域一致，候选统计齐全 |
| 精炼油 60/min，含副产物 | 四模式×普通/密铺×1/2/4 worker | 全部成功，串并行输出一致 |
| 电磁矩阵 60/min，所有支持配方使用四点加速喷涂，Mk.III 带/臂，开启供剂网络 | 四模式×普通/密铺×1/2/4 worker | 全部成功，含增产剂生产链，串并行输出一致 |
| 氢 60/min，选择原生配方 58 的毛流回收 | 四模式×普通/密铺×1/2/4 worker | 直连带及密铺组合成功且一致；普通配送/普通塔按既有边界一致拒绝 `GEN_E_PORT_UNVERIFIED`，没有放宽规则 |
| 四点喷涂但仍选 Mk.I 臂 | 四模式×普通/密铺×1/2/4 worker | 一致拒绝容量不足，不返回部分蓝图 |

额外验证固定波次同时最多四项执行、归约在整波退出后按序发生；取消后所有已启动 worker 退出才返回；旧任务未释放执行槽时新任务不能进入。真实密铺配送在首次候选开始后取消，返回错误、无部分蓝图，返回后无迟到事件。

日志验证覆盖最近任务淘汰、显式关闭、非法序号和逐页重建；无法恢复时返回 incomplete，不返回假完整状态。

### 耗时样本

以下为同一台机器上的单次离线样本，包含检查点、事件归档及验证开销，不是统计基准或线性加速承诺。输入为 600/min 电磁矩阵、自动球面布局。

| 模式/密度 | 一 worker | 四 worker | 建筑数 |
| --- | --- | --- | --- |
| 直连带/普通 | 1.161 s | 0.892 s | 1504 |
| 配送/普通 | 6.354 s | 3.027 s | 1823 |
| 行星塔/普通 | 2.264 s | 1.235 s | 1663 |
| 星际塔/普通 | 2.350 s | 1.150 s | 1663 |
| 直连带/密铺 | 3.918 s | 2.634 s | 1252 |
| 配送/密铺 | 4.751 s | 2.482 s | 2012 |
| 行星塔/密铺 | 1.291 s | 0.885 s | 1535 |
| 星际塔/密铺 | 1.319 s | 0.899 s | 1535 |

存在单个候选主导耗时的输入：例如喷涂后的普通行星塔，串并行都接近 37–40 秒。当前并发粒度为候选，不拆分单个候选的寻路，因此不保证每种输入都明显加速。

## 浏览器行为证据

浏览器运行真实渲染包、真实 useAlgorithmFeed 和订阅封装；传输层使用离线引擎导出的真实事件及日志分页响应。此项验证实际前端行为，不等同于最新 Wails 宿主端到端验证。

- 60/min 密铺配送：702 项过程事件，24 个完整平台，最终只剩候选 7 的 302 个建筑；native GLB 与 KTX2 贴图可见。
- 600/min 密铺配送：916 项过程事件，24 个预声明平台；超过 20000 个排队操作后继续从日志读取，最终接收数量恰好为 916，只剩候选 3 的 2012 个建筑，无过程不完整提示。
- 人工停止投递后补发、反向发送并重复投递，均按原序号无重复恢复；日志读取期间取消，迟到事件数量为零；过期日志只产生一次显式提示。
- 在暂停状态跳过大队列，后续日志尾部也立即应用；最终队列零、动画零、一个平台、2012 个建筑。新任务会重置跳过状态。
- 主动触发 WEBGL_lose_context，在上下文丢失时切换任务，恢复后仅保留新任务一个建筑、一个平台，GPU 重新绘制，没有旧对象回流。
- rAF 采样包含等待和收尾，不能替代目标设备的动画期间 GPU/帧时间基准；该性能验收仍保留为待办。
