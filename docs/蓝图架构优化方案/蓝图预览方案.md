# 蓝图预览前端对接指南

最新版协议字段、事件顺序及恢复规则见[蓝图预览协议 v4（当前实现汇总）](../蓝图预览协议-v4.md)。本文保留接入说明与 v3 单场景兼容示例。

本文面向前端工程师，说明何时接入蓝图过程预览、如何调用接口和处理事件，并提供任务切换、失败处理与页面清理的完整示例。

## 多候选演示（v4）

算法可视化现使用 `emitPreviewDeltas: true` 和 `previewProtocolVersion: 4`。下文 v3 为单场景兼容协议；v4 不可直接合流到一份对象列表。详细架构见[候选并发计算与多平台算法可视化方案](候选并发计算与多平台算法可视化方案.md)。

v4 生命周期为 `search-start → candidate-plan → candidate-start → preview-delta* → candidate-finish`，候选之间可交错。`candidate-plan.candidates` 提供完整候选组，按 `id` 与 `ordinal` 先铺开全部平台；条件回退组仅在启用时追加。候选事件包含 `candidateId`、`candidateOrdinal` 和严格递增的 `candidateSequence`，任务事件仍由全局 `sequence` 保证发送顺序。对象与连接的唯一身份为 `(taskId, candidateId, objectId)`。

`candidate-finish.candidateStatus` 为 `valid / rejected / pruned`。失败候选等自己的已排队过程播完即独立坠落；可行候选等待最终选择。搜索整体失败使用 `search-failed`，不选出虚假的胜者。

获选候选的正式姿态通过 `preview-snapshot` 完整分块发送：`snapshotRevision` 标识快照版本，`chunkIndex`（第一块缺省为零）和 `chunkCount` 标识分块，每块最多 128 项 add 操作。前端验证所有分块、对象唯一性及最终 `buildingCount`，在 `preview-complete` 后组装为一个快照；`winnerCandidateId` 同时存在于完成事件和正式返回值，两者一致且调用成功才允许最终视觉结算。完整快照排在获选候选此前的过程之后，避免逐块进入半定稿状态。

Wails 新增 `ReadGenerationProgress(taskId, afterSequence)`，返回 `{events, next, complete, incomplete, message}`，每页最多十六项原始事件。服务在实时发送前归档，最近两次任务各最多 64 MiB、十分钟有效期；应用正常退出时删除文件。序号缺口与丢失的尾事件可由日志恢复。`incomplete` 必须显示为过程不完整，不能继续假定画面正确；恢复入口不改变计算结果。

订阅封装会过滤任务、去重、按序补发，并在渲染队列积压时延迟从日志继续读取。业务调用可先返回正式蓝图，订阅仍会补齐未播放的尾部记录，直到完整结束或被新请求/卸载取消。`algorithm-viz` 使用 `pace: 'cinematic'`，播放速度独立于计算，不再以一秒内追赶后端为目标。

## 1. 先理解要接什么

可以把这套接口理解为：后台一边生成蓝图，一边告诉前端“增加这些建筑”“撤掉这些建筑”“更新这些建筑”。前端按消息更新画面，决定怎么出现、怎么移动、怎么消失。

例如，一台机器先放在左边，后来后台换了一个位置，前端就按更新消息移动它；后台撤销了一段传送带，前端就按删除消息撤下它。前端无需判断为什么调整位置，也无需识别某种模式的算法规则。

接入时有两条数据线：

| 数据 | 用途 | 什么时候收到 |
| --- | --- | --- |
| 增量预览事件 | 展示正在生成的临时建筑与路线 | 生成过程中陆续收到 |
| 正式生成结果 | 展示最终蓝图，以及复制、保存、导出 | `generateFactory` 成功返回后 |

增量事件只包含发生变化的对象。正式蓝图串在最终结果中取得，不需要在每次事件后重新拼接、解析和加载。

## 2. 什么时候对接

**开发阶段现在就可以开始对接。** 后端已有事件接口和前端订阅封装，模型显示和增量动画由 `frontend/src/packages/algorithm-viz` 提供；应用层组件为 `components/dysonSphere/factory/algorithm-stage.vue`，事件适配由 `useAlgorithmFeed.ts` 负责。

**运行时，在用户发起一次蓝图生成时接入。** 预览组件准备好之后再开始生成；先订阅、后提交生成请求。推荐使用 `generateFactory`，它已经处理这个顺序及 v4 日志补发，不需要页面再额外订阅一次。

```text
用户点击生成，或自动刷新触发生成
  → 准备本次临时预览
  → 调用 generateFactory，开启差量选项
  → 封装自动订阅，再提交生成请求
  → 回调陆续收到事件，前端增量更新画面
  → 生成调用成功：采用正式结果
  → 生成调用失败：丢弃本次临时预览，保留上次成功结果
```

| 页面发生的事情 | 对接动作 |
| --- | --- |
| 首次打开页面，还没有生成任务 | 准备预览组件即可，不需要启动任务订阅 |
| 点击生成或参数变化后开始重新生成 | 建立新的任务预览，开启事件回调 |
| 一次生成尚未结束，又发起新的生成 | 停止观察旧任务，清空旧任务的临时对象，再接新任务 |
| 收到 `preview-complete` | 标记本次预览事件流结束，继续等待生成调用返回 |
| `generateFactory` 成功返回 | 使用返回的 `result.blueprint` 作为正式蓝图 |
| 生成报错 | 清理本次临时对象，展示错误并保留上一次成功结果 |
| 离开页面、组件卸载或关闭过程预览 | 停止观察，清理本次临时对象和动画队列 |

v3 没有补发历史事件或恢复过程快照的能力。v4 可按已知任务 ID 补发仍在有效期内的过程日志；没有任务身份或日志已过期时，重新发起生成，或者等待正式结果回放。

## 3. 从哪个接口接

推荐入口为 `frontend/src/pages/services/dysonSphere/factory.ts`：

```ts
generateFactory(request, onProgress?, signal?)
```

| 参数或返回值 | 前端怎么使用 |
| --- | --- |
| `request` | 沿用已有生成参数，增加 `emitPreviewDeltas: true` |
| `onProgress` | 收到阶段信息与预览事件时调用，在这里把变化交给预览模块 |
| `signal` | 使用 `AbortController.signal` 停止观察旧任务或已关闭的页面 |
| 返回的 Promise | 成功时得到正式生成结果，失败时进入 `catch` |

这里的 `request` 仍然需要完整的生成输入，例如已有量化结果 `plan`、生成模式 `mode` 和配置 `setting`。只传 `emitPreviewDeltas` 不能生成蓝图。

封装会自动生成 `taskId`、过滤其他任务的事件、校验事件结构，并在调用结束时解除订阅。通过此入口接入时，不需要自己填写 `taskId`；即使请求中已有这个字段，封装也会为本次调用重新分配。

只需要过程差量时，将 `emitBlueprintProgress` 设为 `false`，避免同时接收旧的最终建筑分块。未设置 `emitPreviewDeltas` 时，保持普通生成方式。

## 4. 收到事件后做什么

`onProgress` 不仅接收建筑变化，也会接收阶段文案。先看 `kind`，再决定用途：

| `kind` | 含义 | 前端处理 |
| --- | --- | --- |
| `phase` | 当前正在处理哪个阶段 | 更新状态文案，不修改建筑列表 |
| `preview-delta` | 一批对象发生变化 | 按顺序应用 `operations` |
| `preview-complete` | 本次预览数据发送完毕 | 记录结束状态，不据此覆盖正式结果 |
| `building-batch` | 兼容旧接口的最终建筑分块 | 本次实时差量方案不需要使用 |
| 未提供 `kind` | 封装可能发送的读取结果进度等信息 | 按普通状态文案处理 |

实时差量、最终建筑分块及其完成事件使用 `protocolVersion: 3`；普通阶段事件仍可能是版本 1。不要把整个回调限制为只接收版本 3，否则会丢失阶段文案。

v3 的预览载荷不兼容 v2 差量和 v1 建筑分块结构，消费者需同步升级；当前入口只继续兼容 v1 阶段及完成事件，不会把旧格式的预览载荷当作新格式处理。

每条差量事件最多携带 128 项操作，差量中的 `operations` 只有三种：

| 操作 | 含义 | 对象数据 |
| --- | --- | --- |
| `add` | 增加一个建筑或路线片段 | 包含完整的 `building` 预览数据 |
| `remove` | 删除当前显示的对象 | 只有 `objectId`，不重复携带建筑数据 |
| `replace` | 更新已有对象 | 包含该对象新的完整 `building` 数据，不是局部字段补丁 |

前端可使用 `Map<objectId, building>` 保存当前对象。`objectId` 是本次任务中的稳定身份；不要用建筑数组下标或 `building.index` 代替它，也不要跨任务复用它。

### 4.1 `preview-delta` 中单项操作的字段

下面是一条 `operations` 数组中的实际结构。为把类型和含义放在字段旁，示例使用带注释的 JSON（JSONC）；发送到前端的真实事件不含这些注释。`building` 只提供过程预览所需的渲染数据，不包含完整蓝图记录的过滤器和参数数组；仅有两个按需省略的展示字段 `recipeId`（机器配方）与 `iconItemId`（传送带标记物品），供前端在建筑与带入口上方显示图标，缺失或为零时只是不显示图标。

```jsonc
{
  "type": "add",                 // string："add" 新增；"replace" 用完整 building 替换；"remove" 删除且不带 building
  "objectId": "building-355",    // string：本次任务内稳定的对象 ID；用作 Map 键，不能用 building.index 代替
  "building": {                   // object：add/replace 必需；remove 时不存在
    "index": -1,                  // number（整数）：最终蓝图记录索引；临时对象为 -1，不代表对象无效
    "isTemporary": true,          // boolean：layout-grid-v1 中为 true；提交 blueprint-area-local-v1 后为 false
    "itemId": 2001,               // number（整数）：建筑物品原型 ID；项目原版数据中 2001 为“传送带”
    "modelIndex": 35,             // number（整数）：模型原型索引；与 itemId 一起选择外观
    "areaIndex": 0,               // number（整数）：所属 Area；临时 layout-grid-v1 场景固定为 0
    "localOffset": {              // object：首端位置，按外层 coordinateSystem 解释
      "x": 14,                    // number：首端 X
      "y": 5,                     // number：首端 Y
      "z": 0                      // number：首端 Z（高度）
    },
    "localOffset2": {             // object：次端位置，供分拣器等双端建筑使用；不是第二座建筑
      "x": 14,                    // number：次端 X
      "y": 5,                     // number：次端 Y
      "z": 0                      // number：次端 Z
    },
    "yaw": 90,                    // number：首端朝向角
    "yaw2": 90,                   // number：次端朝向角
    "tilt": 0,                    // number：首端附加姿态角
    "tilt2": 0,                   // number：次端附加姿态角
    "pitch": 0,                   // number：首端附加姿态角
    "pitch2": 0,                  // number：次端附加姿态角
    // "inputObjectId": "building-354", // string，可选：输入连接引用的对象 ID；本条记录未提供
    "outputObjectId": "building-356", // string，可选：输出连接引用的对象 ID，目标可能在后续批次才出现
    "inputFromSlot": 0,           // number（整数）：输入来源对象的槽位；无 inputObjectId 时不能单凭此值画连线
    "outputToSlot": 1,            // number（整数）：输出目标对象的槽位；与 outputObjectId 配合使用
    "productionIndex": -1,        // number（整数）：量化产线下标；-1 表示共享设施或无单独产线归属
    // "recipeId": 6,             // number（整数），可选：机器配方原型 ID；零值省略，仅用于建筑图标
    // "iconItemId": 1101         // number（整数），可选：传送带标记物品 ID；零值省略，仅用于带入口图标
  }
}
```

因此，在外层事件的 `coordinateSystem` 为 `layout-grid-v1` 时，这条示例可以读作：**在临时布局坐标 `(14, 5, 0)` 新增一个传送带预览对象，朝向值为 `90`，它的输出引用 `building-356` 的目标槽位 `1`，归属为共享设施。** 若外层坐标系不同，必须先按该坐标系解释位置；只有后续收到 `building-356`，才能把这条输出连线完整画出。临时对象的 `index: -1` 不能拿来与最终蓝图记录逐项对号入座。

一条事件内的操作按数组顺序处理，不同事件按 `sequence` 顺序处理。`sequence` 与阶段事件共享计数，因此两次差量之间出现跳号是正常现象，不能直接判断为丢包。每次新生成都重新记录序号；重复或更旧的序号可忽略。

当渲染速度跟不上事件速度时，回调只负责快速收下数据，绘制可集中到下一帧执行。动画可以跳过中间视觉过渡，但对象的新增、更新、删除顺序必须保持正确。预览模块应在内部处理渲染异常，避免向事件回调外抛错。

## 5. 一次建筑调整的例子

下表用于解释合法操作的含义，不代表每次生成都会采用相同的尝试顺序：

| 后台发来的变化 | 前端此时看到什么 |
| --- | --- |
| `add building-1`，位置为 `(0, 0, 0)` | 第一台机器出现在原点 |
| `add building-2`，位置为 `(3, 0, 0)` | 第二个对象出现 |
| `replace building-1`，位置改为 `(0, 2, 0)` | 第一台机器移动到新位置 |
| `remove building-2` | 第二个对象被撤下 |
| `add building-3`，位置为 `(4, 2, 0)` | 新对象出现 |

前端只执行这五次对象变化。即使其中发生了候选切换或算法回退，也不需要额外理解回退原因，更不需要等待整张蓝图完成后再模拟这个过程。

## 6. 完整调用案例

下面示例说明生成页面如何连接接口与自己的预览组件，**不是仓库中已经提供的渲染器**。`PreviewView` 的各个方法由前端预览模块实现；示例只处理生成、消息转交、任务切换和清理。

示例假设代码放在 `frontend/src/composables/useBlueprintPreview.ts`，导入路径按这个位置书写；本次仅提供文档，不创建该文件。

```ts
import {build} from '../../wailsjs/go/models'
import {generateFactory} from '../pages/services/dysonSphere/factory'
import type {FactoryGenerationProgress} from '../types/factory-progress'

interface PreviewView {
  begin(): void // 清空临时对象，保留上一次成功结果
  applyDelta(event: FactoryGenerationProgress): void // 接收有序差量
  setStatus(message: string): void
  commit(blueprint: string): void // 采用正式结果，并结束本次临时预览
  discard(): void // 清理临时对象和待播放动画，不删除上次成功结果
  showError(message: string): void
}

export function createPreviewConnection(view: PreviewView) {
  let active: AbortController | undefined

  async function generate(request: build.Request): Promise<void> {
    active?.abort()
    const current = new AbortController()
    active = current
    let lastSequence = 0
    view.begin()

    try {
      const result = await generateFactory(
        new build.Request({
          ...request,
          emitPreviewDeltas: true,
          emitBlueprintProgress: false,
        }),
        event => {
          if (current.signal.aborted) return
          if (event.sequence !== undefined) {
            if (event.sequence <= lastSequence) return
            lastSequence = event.sequence
          }
          if (event.kind === 'preview-delta') {
            view.applyDelta(event)
          } else {
            // 包括阶段和预览完成消息；正式成功以调用返回为准。
            view.setStatus(event.message)
          }
        },
        current.signal,
      )

      // 防止旧任务的迟到结果覆盖新任务。
      if (!current.signal.aborted) view.commit(result.blueprint)
    } catch (error) {
      if (current.signal.aborted) return
      view.discard()
      view.showError(error instanceof Error ? error.message : '生成失败')
    } finally {
      if (active === current) active = undefined
    }
  }

  function stop(): void {
    active?.abort()
    active = undefined
    view.discard()
  }

  return {generate, stop}
}
```

页面创建一次连接后，在“生成”按钮或自动刷新入口调用 `connection.generate(request)`；离开页面或关闭过程预览时调用 `connection.stop()`。Vue 的组件卸载、KeepAlive 页面停用等生命周期，可在对应位置调用同一个清理方法。重新进入页面时，按需要重新发起生成。

**这里的 `stop()` 是停止前端观察。** 当前 `AbortSignal` 会解除监听、阻止旧结果进入页面并停止后续蓝图分片读取，但不会终止已经执行的 Go 生成任务，也不会让正在等待的生成调用立即返回。页面应立即结束自己的临时预览，不必等待旧调用结束。

## 7. 坐标与完成状态的注意点

生成过程和最终结果存在两种坐标语义：

| `coordinateSystem` | 含义 | 处理方式 |
| --- | --- | --- |
| `layout-grid-v1` | 生成中的临时布局格坐标 | 用作过程展示，不直接当作行星上的世界坐标 |
| `blueprint-area-local-v1` | 最终蓝图 Area 内的局部坐标 | 结合事件附带的 `areas`、`primaryAreaIndex` 解释位置 |

预览事件中的 Area 使用嵌套结构：`anchorLocalOffset: {x, y}` 与 `size: {x, y}`。这是预览 DTO，不改变蓝图编解码内部的扁平 Area 记录。坐标系发生切换时，后端会对保留对象发送 `replace`。前端应先按当前事件更新坐标解释，再应用这批变化，并缓存最终区域信息；完成事件不再重复发送全部区域与建筑。尚未实现 Area 坐标转换时，可先完成临时布局的平面展示，正式结果仍交给现有最终蓝图查看器。

例如，宽 52、高 32 的区域元数据为：

```json
{"index":0,"parentIndex":-1,"tropicAnchor":0,"areaSegments":200,"anchorLocalOffset":{"x":0,"y":0},"size":{"x":52,"y":32}}
```

`isTemporary` 与坐标阶段绑定，不根据 `stage` 文案推断：`layout`、`assembly`、`routing` 等阶段中，采用 `layout-grid-v1` 的建筑均为 `true`，且 `index` 为 -1；最终提交到 `blueprint-area-local-v1` 时为 `false`，`index` 保留正式记录索引。最终建筑分块中的建筑同样显式携带 `isTemporary: false`。`false` 只说明这是正式预览记录，不表示已通过游戏内放置验收。`remove` 操作仍不携带建筑载荷。

`building` 包含模型、两端位置、朝向等预览字段；连接关系可使用 `inputObjectId`、`outputObjectId`。某个关联对象可能在后续批次才出现，渲染模块应允许暂时缺少关联对象，不把它当作生成失败。

`preview-complete` 中的 `buildingCount` 是最终对象数，`batchCount` 是本次实际发送的差量批次数；它们不是所有阶段的进度百分比。收到完成事件后，先处理完已接收的操作；正式保存、导出与成功状态仍以 `generateFactory` 的最终返回为准。

没有收到差量时，可以继续显示阶段文案。第一批对象出现前可能仍在准备数据，不能因为短时间没有建筑事件就判断任务失败。若预览模块自身无法继续处理，则停止本次临时预览，回退到正式结果查看方式，不修改后端的生成决策。

## 8. 对接时需要看的文件
