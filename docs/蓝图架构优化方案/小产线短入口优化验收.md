# 小产线短入口优化验收

复现：200/min 磁线圈、超密度、传送带模式、三级传送带与三级分拣器，其它设备默认一级，赤道环中心。完整生产计划 ID 为 `be12ed68c33206551644f7dc122fce2b`，10 台生产设备，原料为铁矿 200/min、铜矿 100/min。

## 原因与修改

接驳每个高度只保留两个候选。向前与侧移等长时，旧排序按坐标选择，导致直出候选被两条侧移挤掉，出现入口先侧移再折返的 U 形路线。现在只对外部入口的源端优先保留同距离直出；目标端和厂内接驳保持原顺序，不能为了短入口影响内部端口可达性。直出被占用时仍能选择侧移。

联合边界的全部原料头都处于地面时，尝试将七格预留收缩到三格。先用真实模型盒、带节点和完整带段检查输入短接、输出尾带及第一步厂内接入；任一不成立就保留原方案。三层密集入口不缩短，不取消节点、带段交叉或最终球面验证。

## 实测

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 包络面积 / 格² | 220 | 176 |
| 传送带数量 | 127 | 113 |
| 总带长 / 米 | 159.264 | 139.842 |
| 全部实体 | 161 | 147 |
| 生产设备 | 10 | 10 |
| 原料入口 | 2 | 2 |

占地减少 20%，传送带减少约 11%。完整生产计划及逐边输入输出流量一致。两条原料入口的前四个实际节点均为向内直线，没有起步侧移。未改动输入带等级、分拣器等级、产量或原料份额。生成记录约 1.16 秒，非隔离性能基准。

验证覆盖四个朝向的直出候选保留、被占用后的侧移退路、单层收缩、多层不收缩、真实模型盒挡路时不收缩。通过公开生成接口导出并严格解码，重新编码后 Buildings 和 Areas 完全相同。用当前算法可视化及真实模型查看前后完整蓝图，147 个实体加载、末对象选择与队列排空通过，没有脚本异常。

跨规模回归：60/min 信号塔（一级带，377 台生产设备）通过，11,421 个实体；60/min 行星内物流运输站（一级带，2807 台生产设备）通过，210,518 个实体、244 个原料入口，记录耗时 104.806 秒。扩大直出优先到厂内端口的试验版本导致大厂回归失败，未采用。

Wails 完整构建通过（含 frontend 类型检查和 Vite 构建）；限定入口作用范围后再次执行 `wails build -m -nosyncgomod -skipbindings -s` 更新 Windows 应用。没有绑定签名变更。

## 已知限制与证据

同配置开启流速监测器时，修改前及最终版本均出现 `GEN_E_FLOW_MONITOR`：独立合并交付尾带缺少同时满足净空与供电的监测位置。这个既有问题尚未修复；不能把本次未开启监测器的验收泛化到该配置。尚未执行游戏内实拍。

样例位于 `build/bin/appData/blueprints/磁线圈 200 每分钟-短入口优化.txt`。同目录的 `小产线短入口优化证据.zip` 保存复现配置、结果对比、蓝图、前后截图、回归报告及测试源码；Go overlay 复跑时应替换绝对路径。临时测试入口和渲染环境不保留在正式源代码中。工作区原有前端及压缩日志修改不属于本次提交。
