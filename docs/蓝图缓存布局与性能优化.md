# 超密度缓存布局与生成性能

缓存保持旁路语义：主物流不依赖箱臂或库存吞吐。超密度箱体独立填入真实机器间隙，局部主带两端缩短一格；储液罐的双优先门与支路缩短占地。普通布局继续使用原有的固定箱体接驳。

## 顶部扩建空间

对小型储物仓、大型储物仓和储液罐，按原版建造盒横截面在顶面上方保留竖向空间，覆盖生成器最大走线高度。该约束只在超密度布局启用，不把顶部预留变成地面独占空地。

局部轮廓检查、三维寻路索引及最终浮点记录审计都检查真实带段；两端点在仓外、线段穿过仓顶的情况同样拒绝。最终规则报告新增 `storage-roof-clearance`。配送器等库存自身的附加设施不作为传送带处理。

## 性能改动与边界

- 多终点寻路使用有界分页索引；页按代次隔离，只在本轮首次写入时清空。分数坐标和过大范围保留原后备索引。
- 每个候选的串行寻路复用节点块和堆容量，节点状态每轮完整初始化，返回路线只含坐标值。
- 目标包络之外不查询目标坐标哈希；已知无法改善的邻边不重复检查净空；节点启发值在同一固定目标集内复用。发现新节点或真正松弛时仍执行原硬规则。
- 平移压缩复用各单元空间索引，只重建真正移动的单元。宽相位按共享空间桶判断，考虑端口的四舍五入偏移。
- 动态规则检查在明确的只读阶段复用世界端点，结束即释放快照。第二端点直接映射，避免复制整个建筑记录数组。
- 接驳候选先比较代价，只为获选出口分配路径；没有原生端口许可时不分配空权限表。
- 缓存模式会规范化不能生成实际结构的候选修饰，去重后仍保留独立物流塔等有效能力。
- 原生分拣器先验证全部首选端点，已经无碰撞时直接采用，避免构造无用的备选约束图。存在冲突时按实际OBB冲突拆成独立组件，使用冲突位图及前向检查。互不关联的设备不再参与彼此的回溯，仍保留原回溯预算。
- 原生布局分流同时估算制造设备和容量拆行产生的缓存负担。大型缓存塔厂优先比较均衡矩形，自动并发使用两个工作槽；显式并发设置仍受尊重。首次完整终检成功后最多继续比较五秒，只交付完整可行候选。

正交球面迁移以宿主所在行补偿分流器南北短接头，修正逐点缩放造成的剪切，不放宽槽口射线误差。最终喷涂供剂检查使用与原生单元相同的经向缩放，避免把实际接通的供剂带误判为断线。

不降低原碰撞阈值、传送带或分拣器容量，也不删除最终连接、端口、回流、供电与球面检查。

## 对照验证

测试包括分页与原坐标映射随机对照、复用索引与完整重建碰撞索引对照、第二端点与原复制算法逐值比较，以及随机小网格多终点寻路与独立Dijkstra参照比较。

另外包含分拣器约束求解与小规模完整穷举对照、无关端点不会耗尽回溯预算的反例、进出两个方向的球面分流器短接头，以及180台设备加缓存后的原生布局分流。

完整生成回归继续覆盖普通/超密度四种模式、缓存、喷涂、回流、监测器、低等级运输及高纬。随机请求和性能剖析文件保存在 `runtime-shots/cache-optimization/`；耗时和内存分配是当前机器上的实测，不代表游戏内运行产量或峰值内存。
