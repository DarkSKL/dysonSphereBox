# 模型资源调用与预览器接入指南

模型位于 `frontend/src/data/models/`，基础贴图已内嵌在 GLB 中，格式为 KTX2。原生涂装遮罩和发光、特效图分别位于 `masks/`、`lighting/`，由现有渲染器通过 `maskUrls` 按需加载。模型通过 `?url` 导入：开发时读取原版，打包时自动替换为所选压缩档位。

以下 Vue 页面示例按 `frontend/src/pages/` 的相对路径编写，换目录时调整导入路径。建筑操作的前端事件通知见第 6 节。

## 1. 直接使用项目现有渲染器

把下面代码放入 Vue 页面，即可显示一个制造台。入口来自已有的 `algorithm-viz` 模块，支持建筑操作动画、视角控制和原生材质。

```vue
<script setup lang="ts">
import {onMounted, onBeforeUnmount, ref} from 'vue'
import {createAlgorithmViz, type AlgorithmVizController} from '../packages/algorithm-viz/src'
import {eventBus} from '../utils/event-bus'
import modelUrl from '../data/models/assembler-1.glb?url'
import paintMaskUrl from '../data/models/masks/mask-2903.png?url'
import basisJs from 'three/examples/jsm/libs/basis/basis_transcoder.js?url'
import basisWasm from 'three/examples/jsm/libs/basis/basis_transcoder.wasm?url'

definePage({meta: {layout: 'main', title: '模型预览', keepAlive: false}})
const host = ref<HTMLDivElement | null>(null)
let viewer: AlgorithmVizController | null = null

onMounted(() => {
  if (!host.value) return
  viewer = createAlgorithmViz(host.value, {
    theme: 'dark',
    modelUrls: {'assembler-1': modelUrl},
    transcoderUrls: {js: basisJs, wasm: basisWasm},
    maskUrls: {'2903': paintMaskUrl},
    // 建筑生命周期回调转发到前端业务总线，其他组件即可独立订阅。
    onBuildingBefore: event => eventBus.emit('algorithm:building:before', event),
    onBuildingAfter: event => eventBus.emit('algorithm:building:after', event),
  })
  viewer.enqueue({
    taskId: '', // 独立模型预览没有生成任务。
    coordinates: 'layout',
    operations: [{
      type: 'add',
      id: 'machine-1',
      building: {itemId: 2303, x: 0, y: 0, z: 0, yaw: 0},
    }],
  })
})

onBeforeUnmount(() => viewer?.dispose())
</script>

<template>
  <div ref="host" style="width: 100%; height: 480px" />
</template>
```

`2303` 是制造台物品 ID，对应模型键 `assembler-1`，遮罩编号为 `2903`。接入多个建筑时，按现有 [algorithm-stage.vue](../frontend/src/components/dysonSphere/factory/algorithm-stage.vue) 的方式批量导入模型和遮罩。

算法舞台还通过 `maskUrls` 映射 `lighting/` 中的发光、特效图；需要完整还原其他建筑材质时，一并参考该组件的资源映射。上面的示例已接入事件发布，监听方式见第 6 节。

已有对象通过相同 ID 更新或移除：

```ts
viewer?.enqueue({operations: [{
  type: 'replace', id: 'machine-1',
  building: {itemId: 2303, x: 4, y: 0, z: 0, yaw: 90},
}]})
viewer?.enqueue({operations: [{type: 'remove', id: 'machine-1'}]})
```

## 2. 接入自己的 Three.js 预览器

如果已有 Three.js 场景，在加载模块中加入下面的函数，例如放在 `frontend/src/utils/model-loader.ts`。它使用项目当前安装的 `GLTFLoader` 和 `KTX2Loader`，处理模型 URL 与 Basis 转码器地址。

```ts
import * as THREE from 'three'
import {GLTFLoader} from 'three/examples/jsm/loaders/GLTFLoader.js'
import {KTX2Loader} from 'three/examples/jsm/loaders/KTX2Loader.js'
import basisJs from 'three/examples/jsm/libs/basis/basis_transcoder.js?url'
import basisWasm from 'three/examples/jsm/libs/basis/basis_transcoder.wasm?url'

export function createModelLoader(
  renderer: THREE.WebGLRenderer,
  modelUrls: Readonly<Record<string, string>> = {},
) {
  const manager = new THREE.LoadingManager()
  manager.setURLModifier(url => {
    const path = new URL(url, document.baseURI).pathname
    if (modelUrls[path]) return modelUrls[path]
    if (path.endsWith('basis_transcoder.js')) return basisJs
    if (path.endsWith('basis_transcoder.wasm')) return basisWasm
    return url
  })
  const ktx2 = new KTX2Loader(manager).detectSupport(renderer)
  const loader = new GLTFLoader(manager).setKTX2Loader(ktx2)
  return {loader, dispose: () => ktx2.dispose()}
}
```

在预览器初始化后调用。这里的 `renderer`、`scene` 使用该预览器已有的实例：

```ts
import modelUrl from '../data/models/assembler-1.glb?url'
import {createModelLoader} from '../utils/model-loader'

const models = createModelLoader(renderer)
const gltf = await models.loader.loadAsync(modelUrl)
scene.add(gltf.scene)
```

原有预览器继续负责相机、光照、渲染循环及模型释放；卸载时再调用 `models.dispose()` 释放转码器。此方式能读取内嵌 KTX2，若要与现有场景的涂装颜色完全一致，还需接入原生材质与遮罩规则。

如果预览器先通过 HTTP 取得模型字节，把上面的 `loadAsync` 换成：

```ts
const url = new URL(modelUrl, document.baseURI).href
const response = await fetch(url)
if (!response.ok) throw new Error(`模型读取失败：${response.status}`)
const bytes = await response.arrayBuffer()
const gltf = await models.loader.parseAsync(bytes, '')
scene.add(gltf.scene)
```

## 3. 预览器固定请求 `/models/xxx.glb`

继续使用上面的 `createModelLoader`，传入固定路径到真实资产 URL 的映射：

```ts
import modelUrl from '../data/models/assembler-1.glb?url'
import {createModelLoader} from '../utils/model-loader'

const models = createModelLoader(renderer, {
  '/models/assembler-1.glb': modelUrl,
})
const gltf = await models.loader.loadAsync('/models/assembler-1.glb')
scene.add(gltf.scene)
```

加载管理器会把逻辑路径换成 Vite 提供的地址，打包后仍能使用压缩版和带哈希的文件名。只有使用这个加载管理器的请求才会被改写；其他库自行发出的 `fetch` 不会自动经过它。

以上 HTTP 读取适用于同一 Wails 页面。若预览器在外部浏览器或其他服务中运行，需要单独的 HTTP 资源服务或静态资源包；当前项目没有提供这个外部服务。`http://wails.localhost/` 只由 Wails 的 WebView 资源处理器响应。

## 6. 算法事件通知

### 6.1 事件命名与触发范围

前端业务事件使用项目封装的 mitt 总线，统一命名为 `模块:功能:触发点`，触发点为 `before` 或 `after`。现有算法建筑事件如下：

| 事件名 | 触发时机 |
| --- | --- |
| `algorithm:building:before` | 单栋建筑开始应用新增或替换操作，尚在队列中等待的操作不触发 |
| `algorithm:building:after` | 该次操作的建筑姿态落定，动画结束或已直接落位时触发一次 |

发布链路为 `场景应用操作 → onBuildingBefore / onBuildingAfter → eventBus.emit → 业务订阅者`。现有 [algorithm-stage.vue](../frontend/src/components/dysonSphere/factory/algorithm-stage.vue) 和第 1 节示例均已转发两个回调；渲染包自身保持独立，由接入方决定是否转发。

`after` 的完成范围是**单栋建筑的一次操作**，包括传送带和分拣器等场景对象。它只描述当时的姿态落定，不保证候选最终获选，也不代表蓝图生成任务成功。当前没有整轮搭建完成的总线事件；整轮生成结果仍由生成任务返回值和工作区状态提供。

后端的 `factory:generationProgress` 仍通过 Wails 进入生成进度订阅链路；本节两个事件描述前端的建筑播放生命周期。接收建筑通知时，使用下述前端总线入口。

### 6.2 事件载荷与身份

两个事件共用 [AlgoVizBuildingEvent](../frontend/src/packages/algorithm-viz/src/types.ts) 类型；事件名与载荷映射集中在 [types/events.ts](../frontend/src/types/events.ts)。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `taskId` | `string` | 所属生成任务；导入蓝图或没有生成任务的独立预览使用空字符串 |
| `sequence` | `number` | 场景内递增的操作序号，用于关联同一次操作的 `before` 与 `after`；重新回放后继续递增 |
| `candidateId` | `string \| undefined` | 候选身份；普通结果回放或独立模型预览可以没有候选 |
| `id` | `string` | 场景对象 ID；相同 ID 的替换仍属于同一对象身份，不等于蓝图记录下标 |
| `building` | `AlgoVizBuilding` | 本次操作的建筑快照，包含物品、位置、朝向及可选的模型、区域、临时状态、配方等信息 |
| `operation` | `'add' \| 'replace'` | 场景实际执行的新增或替换；同 ID 换模型仍为 `replace` |

`building` 只包含可视化描述，不包含蓝图参数原文。其坐标语义沿用入队批次的 `layout` 或 `area` 坐标系；区域拼接和高度转换由场景负责，不能直接把这些字段当成 Three.js 世界坐标。订阅者应只读使用事件快照。

批次入队时固定任务身份，延迟播放的通知不会被归到后续新任务。自建场景可先调用 `viewer.beginGeneration(taskId)`，后续批次缺省沿用该任务；也可在 `enqueue` 中显式传入 `taskId`。导入蓝图应显式传入 `taskId: ''`，现有 `useAlgorithmFeed` 已处理这一点。

总线在当前前端中共享。多个场景同时发布时，订阅者应按 `taskId`、`id` 等身份筛选；独立预览可给对象 ID 加业务前缀。`sequence` 只在所属场景内有效，不能作为全应用唯一编号。

### 6.3 Vue 组件监听

在页面 `<script setup lang="ts">` 顶层调用 [useAppEvent](../frontend/src/composables/useAppEvent.ts)，事件名和回调载荷会自动推导类型：

```ts
import {onActivated, onDeactivated, ref} from 'vue'
import {useAppEvent} from '../composables/useAppEvent'

// =============== 建筑通知展示 ===============
// 说明：记录最近落定的建筑；本例只在缓存页面处于激活状态时更新。
const pageActive = ref(true)
const lastBuildingId = ref('')
onActivated(() => { pageActive.value = true })
onDeactivated(() => { pageActive.value = false })

const stopBuilding = useAppEvent('algorithm:building:after', event => {
  if (!pageActive.value) return
  lastBuildingId.value = event.id
  console.log('建筑操作完成', event.operation, event.building.itemId)
})
```

作用域销毁时自动取消订阅，也可在不再需要监听时调用 `stopBuilding()`。`useAppEvent` 必须在 `setup` 或有效的 `effectScope` 中注册；组件内应直接在 `setup` 同步注册。

KeepAlive 停用会保留作用域，因此订阅仍存在；示例通过激活状态判断是否处理通知。若舞台还会被标签页隐藏，可进一步结合标签页的可见状态判断。页面重新激活时无需重复注册监听。

若只关心正式建筑，可在回调中检查 `event.building.temporary`；这项筛选只排除临时姿态，候选是否最终获选仍须核对生成结果。

### 6.4 普通 TypeScript 模块与自建预览器

普通模块直接使用 [eventBus](../frontend/src/utils/event-bus.ts)，并由所属模块或宿主在结束时调用返回的取消函数：

```ts
import {eventBus} from '../utils/event-bus'

const stopBuilding = eventBus.on('algorithm:building:after', event => {
  console.log('建筑落位', event.taskId, event.sequence, event.id)
})

// 模块或宿主结束时调用 stopBuilding()，仅取消本次订阅。
```

第 1 节通过 `onBuildingBefore`、`onBuildingAfter` 转发事件，自建场景按相同方式接入即可。若已有算法舞台负责发布，同一操作只需发布一次，业务订阅者直接监听即可。

第 2、3 节直接使用 Three.js 加载模型的预览器，需要自行对接真实建筑操作的开始和完成时机，再调用 `eventBus.emit`。GLB、KTX2 加载结束只表示资源可用；建筑落位完成应由预览器自身的操作或动画生命周期判断。`BlueprintViewerPanel` 使用独立的 UMD 预览器，也不会自动发布本节的建筑事件。

新增业务事件时，在 `types/events.ts` 声明符合 `模块:功能:before/after` 命名的事件及载荷，再由拥有该操作生命周期的模块发布。应用业务模块共用现有 `eventBus` 实例。

### 6.5 播放与取消规则

| 场景 | 通知规则 |
| --- | --- |
| 正常新增或替换 | 操作开始发 `before`，姿态落定后发一次对应的 `after` |
| 跳过动画、跟随积压时直接应用、减少动态效果 | 仍按操作开始与落定顺序通知；直接落位时两个通知可能发生在同一次调用中 |
| 同一建筑在落定前被再次替换 | 旧操作不再发 `after`；新操作使用新 `sequence`，以新姿态完成时为准 |
| `remove` 撤销 | 取消该对象尚未完成的通知；撤销本身不发布这两个建筑事件 |
| 候选被淘汰、场景重置或释放 | 尚未完成的旧操作不再发 `after` |
| 模型迟到、占位体补换成真实模型 | 不额外发送建筑通知；`after` 不等待模型资源加载结束 |
| 重新回放 | 重新应用操作并正常发送通知；同一场景的 `sequence` 继续递增 |

已经发出的 `after` 不会因后续替换、撤销或候选淘汰而被撤回。订阅者不能假设每个 `before` 最终都有一个 `after`，也不能只按建筑 ID 把后续替换或重新回放的合法通知过滤掉。

总线同步分发，不保存状态、不重放历史，也不等待异步监听器完成。应在操作开始前注册监听；需要展示当前状态时，将通知写入自己的响应式状态。监听器应保持轻量，异常或异步失败由总线单独记录，不阻断其他订阅者和舞台播放。
