# 模型调用与渲染接入案例

模型位于 `frontend/src/data/models/`，贴图已内嵌在 GLB 中，格式为 KTX2。模型通过 `?url` 导入：开发时读取原版，打包时自动替换为所选压缩档位。

以下 Vue 页面示例按 `frontend/src/pages/` 的相对路径编写，换目录时调整导入路径。

## 1. 直接使用项目现有渲染器

把下面代码放入 Vue 页面，即可显示一个制造台。入口来自已有的 `algorithm-viz` 模块，支持建筑操作动画、视角控制和原生材质。

```vue
<script setup lang="ts">
import {onMounted, onBeforeUnmount, ref} from 'vue'
import {createAlgorithmViz, type AlgorithmVizController} from '../packages/algorithm-viz/src'
import modelUrl from '../data/models/assembler-1.glb?url'
import paintMaskUrl from '../data/models/masks/mask-2903.png?url'
import basisJs from 'three/examples/jsm/libs/basis/basis_transcoder.js?url'
import basisWasm from 'three/examples/jsm/libs/basis/basis_transcoder.wasm?url'

definePage({meta: {layout: 'main', title: '模型预览', keepAlive: false}})
const host = ref<HTMLDivElement | null>(null)
let viewer: AlgorithmVizController | null = null

onMounted(() => {
  if (!host.value) return
  viewer = createAlgorithmViz(host.value, {
    theme: 'dark',
    modelUrls: {'assembler-1': modelUrl},
    transcoderUrls: {js: basisJs, wasm: basisWasm},
    maskUrls: {'2903': paintMaskUrl},
  })
  viewer.enqueue({
    coordinates: 'layout',
    operations: [{
      type: 'add',
      id: 'machine-1',
      building: {itemId: 2303, x: 0, y: 0, z: 0, yaw: 0},
    }],
  })
})

onBeforeUnmount(() => viewer?.dispose())
</script>

<template>
  <div ref="host" style="width: 100%; height: 480px" />
</template>
```

`2303` 是制造台物品 ID，对应模型键 `assembler-1`，遮罩编号为 `2903`。接入多个建筑时，按现有 [algorithm-stage.vue](../frontend/src/components/dysonSphere/factory/algorithm-stage.vue) 的方式批量导入模型和遮罩。

已有对象通过相同 ID 更新或移除：

```ts
viewer?.enqueue({operations: [{
  type: 'replace', id: 'machine-1',
  building: {itemId: 2303, x: 4, y: 0, z: 0, yaw: 90},
}]})
viewer?.enqueue({operations: [{type: 'remove', id: 'machine-1'}]})
```

## 2. 接入自己的 Three.js 预览器

如果已有 Three.js 场景，在加载模块中加入下面的函数，例如放在 `frontend/src/utils/model-loader.ts`。它使用项目当前安装的 `GLTFLoader` 和 `KTX2Loader`，处理模型 URL 与 Basis 转码器地址。

```ts
import * as THREE from 'three'
import {GLTFLoader} from 'three/examples/jsm/loaders/GLTFLoader.js'
import {KTX2Loader} from 'three/examples/jsm/loaders/KTX2Loader.js'
import basisJs from 'three/examples/jsm/libs/basis/basis_transcoder.js?url'
import basisWasm from 'three/examples/jsm/libs/basis/basis_transcoder.wasm?url'

export function createModelLoader(
  renderer: THREE.WebGLRenderer,
  modelUrls: Readonly<Record<string, string>> = {},
) {
  const manager = new THREE.LoadingManager()
  manager.setURLModifier(url => {
    const path = new URL(url, document.baseURI).pathname
    if (modelUrls[path]) return modelUrls[path]
    if (path.endsWith('basis_transcoder.js')) return basisJs
    if (path.endsWith('basis_transcoder.wasm')) return basisWasm
    return url
  })
  const ktx2 = new KTX2Loader(manager).detectSupport(renderer)
  const loader = new GLTFLoader(manager).setKTX2Loader(ktx2)
  return {loader, dispose: () => ktx2.dispose()}
}
```

在预览器初始化后调用。这里的 `renderer`、`scene` 使用该预览器已有的实例：

```ts
import modelUrl from '../data/models/assembler-1.glb?url'
import {createModelLoader} from '../utils/model-loader'

const models = createModelLoader(renderer)
const gltf = await models.loader.loadAsync(modelUrl)
scene.add(gltf.scene)
```

原有预览器继续负责相机、光照、渲染循环及模型释放；卸载时再调用 `models.dispose()` 释放转码器。此方式能读取内嵌 KTX2，若要与现有场景的涂装颜色完全一致，还需接入原生材质与遮罩规则。

如果预览器先通过 HTTP 取得模型字节，把上面的 `loadAsync` 换成：

```ts
const url = new URL(modelUrl, document.baseURI).href
const response = await fetch(url)
if (!response.ok) throw new Error(`模型读取失败：${response.status}`)
const bytes = await response.arrayBuffer()
const gltf = await models.loader.parseAsync(bytes, '')
scene.add(gltf.scene)
```

## 3. 预览器固定请求 `/models/xxx.glb`

继续使用上面的 `createModelLoader`，传入固定路径到真实资产 URL 的映射：

```ts
import modelUrl from '../data/models/assembler-1.glb?url'
import {createModelLoader} from '../utils/model-loader'

const models = createModelLoader(renderer, {
  '/models/assembler-1.glb': modelUrl,
})
const gltf = await models.loader.loadAsync('/models/assembler-1.glb')
scene.add(gltf.scene)
```

加载管理器会把逻辑路径换成 Vite 提供的地址，打包后仍能使用压缩版和带哈希的文件名。只有使用这个加载管理器的请求才会被改写；其他库自行发出的 `fetch` 不会自动经过它。

以上 HTTP 读取适用于同一 Wails 页面。若预览器在外部浏览器或其他服务中运行，需要单独的 HTTP 资源服务或静态资源包；当前项目没有提供这个外部服务。`http://wails.localhost/` 只由 Wails 的 WebView 资源处理器响应。

## 4. 直接显示蓝图编码

如果需要复用当前蓝图编码预览组件，父页面直接传入编码：

```vue
<script setup lang="ts">
import BlueprintViewerPanel from '../components/dysonSphere/blueprint/viewer-panel.vue'
defineProps<{blueprintCode: string}>()
</script>

<template>
  <BlueprintViewerPanel :code="blueprintCode" />
</template>
```

这个组件使用 UMD 蓝图预览器的简化几何体，不读取前面的建筑 GLB。需要真实 GLB 时，使用案例 1 或 2。传送带的 GLB 多为空节点，当前渲染包通过连接关系生成带体和动画。

## 5. 打包时选择压缩档位

在项目根目录运行，菜单直接回车选择均衡档：

```powershell
deploy\build.bat v2.1.2
```

也可以直接指定：

```powershell
deploy\build.bat v2.1.2 quality   # 高画质，1024
deploy\build.bat v2.1.2 balanced  # 均衡，512，默认
deploy\build.bat v2.1.2 compact   # 轻量，256
```

前面的加载代码不需要随档位修改。EXE 和 ZIP 输出到 `deploy/release/<版本>/<模式>/`。

运行 `frontend` 下的 `npm run models:compare`、`npm run dev` 后，可打开 `/tools/model-compression/preview.html` 查看实际画质对比。
