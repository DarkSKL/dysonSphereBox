- 机器端会先按真实六槽位、端口流量和所选 `InserterLv` 规划并联分拣器；recipe 9 的 1301 输入在 Mk.I 下会生成两根跨 2 格分拣器（实际能力 45+45/min），因此该回归不再产生容量告警。
- 对仍无法证明吞吐的真实分拣器组，只将 `machine-inserter-capacity` / `inserter-capacity` 标成 `unverified` 并保留原因；不静默升级分拣器、不改变配方/机器数、不伪造 `passed`。
- 端口、槽位、分拣器等级、过滤物品、方向、几何和连接错误仍是硬失败；`UseMixed`、没有产物或输入与产物合计超过六种的端口拓扑仍明确返回 `GEN_E_PORT_UNVERIFIED`，不会创建半成品实体。

空间利用率方面，mode 1、mode 2 和 mode 5 都加入了确定性有限候选。候选先完成实体装配、路线、严格碰撞/表面规则和索引闭合，再按包络面积、带长和稳定 tie-break 选择，不能通过放宽校验换取更小面积。

本轮按后续反馈继续改进：

- **实际线路数量**：mode 1 原料入口就近对应消费者，完整路由后裁除没有任何真实引用的带尾，不再只缩小包络数字。保持机器、分拣器、外供入口、逐边流量和带等级不变。
- **大设备间距**：精炼厂横向中心距由 6 格增加至 7 格，化工厂由 7 格增加至 8 格（含量子化工厂 2317）；用户设置的附加间距继续叠加。其它设备类型不额外加宽。
- **机器端独立出货**：制造台、精炼厂、化工厂等多产物设备按物品分带，出货分拣器设置对应 `FilterID`；不再先混到一条机器带上再二次筛选。剩余副产物保留独立边界出口和原物品 ID 图标。
- **游戏规则边界**：分带避免不同产物在同一带互堵，但设备产出的任何一种副产物满仓仍会让设备停产，需要持续取走。图标只是显示，真正物品过滤由分拣器承担。

用户反馈此前版本“初步测试没问题、空间确实优化了”，并指出线路多、大设备易碰撞。这是有限人工反馈；本轮新增间距、线路和双出口样例尚待用户游戏内复测。

### 多产物、供剂和供电

- `line.outputs` 按 `recipe.Results` 保存实际独立带；`output` 只兼容第一条，业务接驳按 `outputForItem` 精确取带，未知物品不得借首带。

- mode 1/3/4 对每一条出货带分别反向；mode 2/5 直接从本物品机器带接到独立箱体/分流器，移除旧共享出货干线和重复二次过滤。mode 6 仅在首个真实总线交接后允许共享混带环路。

- 供剂入口参考所有真实输入/输出轨的最小 Y，避免底侧产物占位；多产物行在原基线供电之后按真实覆盖补充合法电杆，不扩大电力半径或最小间距。
- 内置十二套数据的配方最多双产物；六口、底侧四产物和七口供剂场景明确使用合成测试，不冒称真实配方。

### mode 2/5（配送器和四向分流）

- 端点份额按真实 source/target 边和单带容量分配，不把整条边流量重复计入多个端点；`InternalConnected` 保持 false。
- mode 2 使用真实配送箱槽位/分拣器跨度；mode 5 使用 Model 39 四向分流器和地面东西向槽位。端点过滤臂、箱体、分流器、带链和机器 owner 均登记并做整条有向链完整性校验。
- 生成器比较 grouped rows、独立机器行和实际轮廓紧凑候选；完整规则通过后才择优。当前测试要求 fixture 0/4 的两种模式相对同版本分组基线至少节省 10% 包络面积，且不增加总建筑、不改变机器、流图 digest、lane 数或关键实体数量。旧版面积快照不是本轮新间距和独立产物带的最终指标。
- 本地分拣器能力按实际 `ItemID`、跨度、等级和唯一实体臂计数；不足只诊断为 `fly-local-inserter-capacity: unverified`。机队吞吐、库存和游戏内产能仍未被离线代码证明。

### mode 3/4（行星/星际物流塔）

- 物流塔物品槽、供需角色、端口、速率、过滤分支、塔间距离和 `planarGridLength` 单位换算均按规范边核验。
- 多产物由本物品独立机器带直接接塔；过滤出口、桥接、升降列、机器堆叠净空、路线首段和正交交叉均纳入严格规则；塔路线不会在最终整理阶段被清空。

### mode 6（混带总线）

- 总线圈、筛选取料、原料 feed/return、目标和副产物边界已接入统一流图，并使用实证分拣器能力和实际闭环实体检查。
- 环路以实际供需位置就近分组，热点圈在有限深度内向邻列溢出；空间候选不能靠增加实际建筑换取更小包络。
- 五个内置 fixture、fixture 0 的三级带以及综合 fixture 的 Mk.I/II 现在要求真实 `Generate` 成功，并独立重建编码后的物品有向图。高流量超出真实圈数/单臂能力时仍保持 fail-closed，不把预算拒绝或断路蓝图当成功。
- 综合 Mk.I 的旧测试写死 303 条 lane；独立产物容量去除了三条冗余 lane，当前为 300 条、141 圈。已更新数量预期并新增规范边身份、逐边份额守恒和单带容量断言，不以减少流量或丢边满足计数。

### 路由和性能

- 三维 A* 保留稳定邻居顺序和同估价 tie-break；每条搜索固定 `300000` 展开、最大高度 `32`，取消和超时会关闭本次生成。
- 已有可行消费端路径后，候选搜索使用 Manhattan 节点数下界剪枝；受长度约束的搜索对同一坐标保留 `(weighted distance, node length)` Pareto 前沿，避免较贵但更短的前缀被错误丢弃。该优化只保证安全剪枝和确定性，不宣称双目标全局最优。
- 路由诊断区分“固定预算耗尽”和“当前候选空间穷尽”，失败不发布部分路线。
