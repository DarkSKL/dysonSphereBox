## 最新补充：汇流断带与速率口径

### 汇流和升降接点

- 已定位一个能解释“两列电动机看似汇入、实际只有一列连接”的实体连接问题：旧记录将所有上游带的 `OutputToSlot` 都写成 1。游戏粘贴时按连接池逐条写入，后写入者会覆盖同一目标槽的旧连接；几何贴近和索引存在不能证明连接最终存续。
- `belt_connections.go` 在最终编号后分配独占的目标带输入槽 1..3，保留设施已占槽，超过可用槽数时硬拒绝；最终规则审计重放粘贴连接池，拒绝被后写覆盖的连接。不通过放宽距离、碰撞或表面规则解决断带。
- `TestPastedConnectionsRealMotorMergeAndVerticalRoutes` 使用真实 fixture 0，强制 11 台电动机制造台分成 6+5 两行，覆盖 flat/auto/explicit 的完整生成、严格解码和独立连接池重放；检查两行到下游消费者的存续路径和升降边。将汇流恢复为全部 slot 1 的破坏反例可以独立重现覆盖断链。
- 单源升降链尚未发现另一个独立根因，不能据此宣称所有垂直断带都已修好；仍需游戏内观察货物真正经过升降和汇流接点。跨 Area 补带另有连接元数据同步和原子回滚测试，但不是完整多 Area 循环物流验收。

### 期望、配置满负荷与实测

- `Production.OutputCount`、原物料流和 `FlowGraph` 继续表示用户需求计划的期望速度；新增 `Production.Capacity`，以 `basis="configured-full-load"` 表示当前整数设备配置的条件满负荷产能、单机产能、等效配方循环、净/毛物料流、利用率和功耗。该字段不修改期望图 digest。
- 前端节点并列显示“期望”和“满负荷（条件值）”；详情区区分整行/单机产能、等效循环和功耗，连线仍明确表示期望净流。尚未进行桌面视觉验收，不能把构建通过当作界面人工验收。
- 实测吞吐是第三种口径，只能由实际供电、供料、出货与计时计数取得，不能把设备理论能力命名为已验证的真实产速。机器没有自动写入降速控制，跨行/节点物流仍按期望净流规划，因此整条蓝图不能仅凭各节点 `Capacity` 就保证同时满载。
- 回归包括 40/min 需求配 45/min 单机、极速带 120/min 需求配 135 条/min 单机、电动机 240/min 需求配 247.5/min 的 11 台配置，以及整数向上取整边界。135.4/min 需求不能因提前四舍五入而只配一台 135/min 设备。

### 原版数据边界、布局选项与生成进度

- 工作台和嵌入资源只保留原版 `Vanilla`；数据集列表、量化、生成、回放及方案导出会拒绝非原版来源。生成入口仅接受模式 1–4：直连带、物流配送器、行星物流塔、星际物流塔；旧模式 5/6 不属于当前产品范围。
- 新球面自动模式隐藏平面排列、单列机器、街区宽度、小数位和权重选项；请求固定关闭历史混带标记和旧供剂网络开关。喷涂仍按量化配置自动生成设备供剂支路及增产剂外部入口，入口必须由玩家在游戏内持续供料。
- `factory:generationProgress` 是请求 ID 隔离的版本化事件。阶段事件默认发送；只有 `EmitBlueprintProgress` 显式启用时，最终严格编码蓝图才会按量化模块发送建筑批次，并用 `preview-complete` 标记完整流。坐标系为 `blueprint-area-local-v1`，建筑索引与连接引用保持最终编码值；缺少完成事件时消费者必须丢弃暂存的部分动画。接口细节见 `生成进度与预览事件协议.md`。
- 动画事件尚未接入预览器的实际增量渲染联动；事件协议只提供稳定数据边界，不冒称已完成动画视觉或游戏内放置验收。

## 本轮结论

用户指出的 recipe 9 / 物品 1301 / 60/min 超过 Mk.I 跨 2 格分拣器约 45/min 的问题已按“结构先生成、能力明确诊断”的原则修复：

- mode 1 不再因为单个分拣器能力预检不足而直接拒绝整个结构。
- 机器端会先按真实六槽位、端口流量和所选 `InserterLv` 规划并联分拣器；recipe 9 的 1301 输入在 Mk.I 下会生成两根跨 2 格分拣器（实际能力 45+45/min），因此该回归不再产生容量告警。
- 对仍无法证明吞吐的真实分拣器组，只将 `machine-inserter-capacity` / `inserter-capacity` 标成 `unverified` 并保留原因；不静默升级分拣器、不改变配方/机器数、不伪造 `passed`。
- 端口、槽位、分拣器等级、过滤物品、方向、几何和连接错误仍是硬失败；`UseMixed`、没有产物或输入与产物合计超过六种的端口拓扑仍明确返回 `GEN_E_PORT_UNVERIFIED`，不会创建半成品实体。

空间利用率方面，mode 1、mode 2 和 mode 5 都加入了确定性有限候选。候选先完成实体装配、路线、严格碰撞/表面规则和索引闭合，再按包络面积、带长和稳定 tie-break 选择，不能通过放宽校验换取更小面积。

本轮按后续反馈继续改进：

- **实际线路数量**：mode 1 原料入口就近对应消费者，完整路由后裁除没有任何真实引用的带尾，不再只缩小包络数字。保持机器、分拣器、外供入口、逐边流量和带等级不变。
- **大设备间距**：精炼厂横向中心距由 6 格增加至 7 格，化工厂由 7 格增加至 8 格（含量子化工厂 2317）；用户设置的附加间距继续叠加。其它设备类型不额外加宽。
- **机器端独立出货**：制造台、精炼厂、化工厂等多产物设备按物品分带，出货分拣器设置对应 `FilterID`；不再先混到一条机器带上再二次筛选。剩余副产物保留独立边界出口和原物品 ID 图标。
- **游戏规则边界**：分带避免不同产物在同一带互堵，但设备产出的任何一种副产物满仓仍会让设备停产，需要持续取走。图标只是显示，真正物品过滤由分拣器承担。

用户反馈此前版本“初步测试没问题、空间确实优化了”，并指出线路多、大设备易碰撞。这是有限人工反馈；本轮新增间距、线路和双出口样例尚待用户游戏内复测。

## 已落地实现

### 统一流图和容量

- `helper/quant` 提供守恒 `FlowGraph`、稳定拓扑/SCC、逐物品供需边和 digest；生成、画板验证和诊断使用同一份规范流边。
- 所选 `BeltLv` 的单带容量统一为 Mk.I/Mk.II/Mk.III `360/720/1800/min`，按实际 lane 数拆分，不静默升级带等级。
- 生产者、消费者、外部入口、目标输出和副产物均保留边界语义；内部边按物品、来源、目标、流量绑定实体路线。
- 输入和每一种产物分别核算实际单带负载。多种产物已经使用独立带，不再将不同物品流量相加导致无谓拆行；任何一种物品超载仍须拆行。
- 最终编码前统一执行守恒、端口、路线交叉/重叠、占位、建造盒、分拣器、物流塔和电力覆盖规则审计；`RuleAudit` 只代表抽象/数值规则已覆盖。

### mode 1（机器直连带）

- 产线机器、输入/输出端口、过滤出口和多带 lane 按规范边自动分配，并完成生产者到消费者的有向接线。
- 真实机器端分拣器规划支持六个槽位内的轨位重排、并联臂和必要的实验室堆叠降低；实际实体会再次重建容量，防止计划摘要与蓝图实体不一致。
- 布局保留矩形基线并增加轮廓凹槽/紧凑候选；候选选择保持机器数、流量、lane 数和路线语义不变。
- 先测试六个就近入口候选；仅全部不可行时再独立重建六个旧集中入口候选。总数最多十二，共享原四分钟期限；最终候选取消不得回传此前的成功候选。
- 输出接驳按离机器最远的物品轨优先，在各自产物轨外侧建立分支；同时考虑真实原料接驳带和 mode 6 动态 stub，避免内侧出货轨穿入原料接口。

### 多产物、供剂和供电

- `line.outputs` 按 `recipe.Results` 保存实际独立带；`output` 只兼容第一条，业务接驳按 `outputForItem` 精确取带，未知物品不得借首带。
- 在六个真实机器槽位内逐物品规划能力，允许有界轨位重排和并联臂；多产物机器出货臂必须精确过滤，错过滤、共享物品带或缺少真实臂属于硬错误。
- mode 1/3/4 对每一条出货带分别反向；mode 2/5 直接从本物品机器带接到独立箱体/分流器，移除旧共享出货干线和重复二次过滤。mode 6 仅在首个真实总线交接后允许共享混带环路。
- belt `Parameters[0]` 使用原物品 ID，`Parameters[1]` 为显示数字；已核实 DLL 与本地查看器语义。`10000+itemID` 不是物品图标编码，已修正。
- 供剂入口参考所有真实输入/输出轨的最小 Y，避免底侧产物占位；多产物行在原基线供电之后按真实覆盖补充合法电杆，不扩大电力半径或最小间距。
- 内置十二套数据的配方最多双产物；六口、底侧四产物和七口供剂场景明确使用合成测试，不冒称真实配方。

### mode 2/5（配送器和四向分流）

- 端点份额按真实 source/target 边和单带容量分配，不把整条边流量重复计入多个端点；`InternalConnected` 保持 false。
- mode 2 使用真实配送箱槽位/分拣器跨度；mode 5 使用 Model 39 四向分流器和地面东西向槽位。端点过滤臂、箱体、分流器、带链和机器 owner 均登记并做整条有向链完整性校验。
- 生成器比较 grouped rows、独立机器行和实际轮廓紧凑候选；完整规则通过后才择优。当前测试要求 fixture 0/4 的两种模式相对同版本分组基线至少节省 10% 包络面积，且不增加总建筑、不改变机器、流图 digest、lane 数或关键实体数量。旧版面积快照不是本轮新间距和独立产物带的最终指标。
- 本地分拣器能力按实际 `ItemID`、跨度、等级和唯一实体臂计数；不足只诊断为 `fly-local-inserter-capacity: unverified`。机队吞吐、库存和游戏内产能仍未被离线代码证明。

### mode 3/4（行星/星际物流塔）

- 物流塔物品槽、供需角色、端口、速率、过滤分支、塔间距离和 `planarGridLength` 单位换算均按规范边核验。
- 多产物由本物品独立机器带直接接塔；过滤出口、桥接、升降列、机器堆叠净空、路线首段和正交交叉均纳入严格规则；塔路线不会在最终整理阶段被清空。

### mode 6（混带总线）

- 总线圈、筛选取料、原料 feed/return、目标和副产物边界已接入统一流图，并使用实证分拣器能力和实际闭环实体检查。
- 环路以实际供需位置就近分组，热点圈在有限深度内向邻列溢出；空间候选不能靠增加实际建筑换取更小包络。
- 五个内置 fixture、fixture 0 的三级带以及综合 fixture 的 Mk.I/II 现在要求真实 `Generate` 成功，并独立重建编码后的物品有向图。高流量超出真实圈数/单臂能力时仍保持 fail-closed，不把预算拒绝或断路蓝图当成功。
- 综合 Mk.I 的旧测试写死 303 条 lane；独立产物容量去除了三条冗余 lane，当前为 300 条、141 圈。已更新数量预期并新增规范边身份、逐边份额守恒和单带容量断言，不以减少流量或丢边满足计数。

### 路由和性能

- 三维 A* 保留稳定邻居顺序和同估价 tie-break；每条搜索固定 `300000` 展开、最大高度 `32`，取消和超时会关闭本次生成。
- 已有可行消费端路径后，候选搜索使用 Manhattan 节点数下界剪枝；受长度约束的搜索对同一坐标保留 `(weighted distance, node length)` Pareto 前沿，避免较贵但更短的前缀被错误丢弃。该优化只保证安全剪枝和确定性，不宣称双目标全局最优。
- 路由诊断区分“固定预算耗尽”和“当前候选空间穷尽”，失败不发布部分路线。
