# 生成进度与预览事件协议

## 事件

- Wails 事件名：`factory:generationProgress`
- 每个生成请求应提供唯一、非空的 `requestId`；前端只处理与当前请求 ID 相同的事件。
- 阶段事件始终可用；建筑预览必须在 `build.Request.emitBlueprintProgress` 显式设为 `true`，缺省为关闭。
- `protocolVersion` 当前为 `1`，`sequence` 在单次请求内严格递增；消费者应忽略未知协议版本和未知 `kind`。

## 事件类型

- `phase`：阶段、说明、当前项和阶段总数，只用于生成状态提示，不是整体百分比。
- `building-batch`：`previewBatch` 携带模块身份、模块内批次序号、建筑记录和 Area 元数据。建筑按 `ProductionBinding` 与共享设施归组，最多每批 128 条。
- `preview-complete`：声明本次预览流完整，并携带建筑数和批次数。只有收到此事件且序号/批次无缺失时，消费者才能提交暂存动画。

## 坐标和索引

- 预览坐标系统为 `blueprint-area-local-v1`。`Building.localOffset`、`localOffset2` 及 `areaIndex` 保持最终编码蓝图记录中的 Area 局部坐标语义；不得自行解释为行星世界坐标。
- `Building.index`、输入/输出连接对象索引、槽位、参数及建筑记录顺序均直接来自最终严格编码蓝图，不在分块时重新编号。
- 每批重复携带 Area 元数据，使消费者无需依赖前一批猜测局部坐标所属区域。模块 ID 在单次请求内稳定，不是跨请求或持久化主键。

## 完整性与失败

- 分块只在布局、规则检查、连接整理、编码及严格自检都成功后，从最终蓝图生成；不会暴露搜索中的候选或被拒绝布局。
- 生成错误、超时或取消可能发生在零个或多个批次之后；没有 `preview-complete` 就代表事件流不完整，消费者必须丢弃暂存状态，而不能将其显示为最终蓝图。
- 该协议只提供动画需要的蓝图数据，不证明游戏内碰撞、物流吞吐或连续产能已经验收。

## 候选与性能诊断

- `phase` 可以新增阶段键，例如 `flow`、`capacity`；消费端应按实际事件显示，不能依赖固定阶段数量推算整体进度。
- 成功结果的 `logisticsSummary.searchCandidates` 按真实评估顺序保存有限候选的稳定键、参数、最后检查阶段、通过/拒绝和原因。内部球面宽度候选使用 `parentKey` 关联外层布局；内部阶段通过不代表外层终检也通过，`passed` 也不等于该候选最终被选中。
- `logisticsSummary.metrics.crossLayerConnections` 从最终实体带到带连接统计高度变化；同XY的独立平行带、水平高架段和带到设施的连接不计为升降。该指标不替代真实连接池、碰撞与容量检查。
- 生成请求显式设置 `collectPerformance: true` 后，成功结果附带 `performance`。默认不返回墙钟字段，以保持普通生成结果的确定性。它与 `emitBlueprintProgress` 相互独立，不增加建筑批次或改变协议版本。
- `performance.scope` 为 `request-all-candidates`：阶段墙钟覆盖整个请求，寻路次数、缓存命中和展开数累计全部已运行候选；碰撞计数按已接入的规则分别记录，不能把它解释为所有几何检查的完整总数。阶段耗时包含同步进度回调时间，不包含性能回调自身。
- 峰值内存、通用取消响应延迟等未测量项列在 `performance.unmeasured`，缺失不是零。各阶段候选计数可能属于嵌套搜索，不能直接相加当作唯一布局数，也不能用一次墙钟测量宣称普遍加速。
- 失败/取消仍返回原错误，不携带半成品结果或性能字段。Go调用方可用 `WithPerformance` 订阅一次最终快照；回调同步执行，应快速返回且不修改引擎。该回调是内部观察接口，不是新增的Wails动画事件。
