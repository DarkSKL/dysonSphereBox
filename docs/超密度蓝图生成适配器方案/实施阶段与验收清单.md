## 1. 不可偏离的交付目标

**四种现有生成模式各自支持普通/超密度开关，超密度的核心成果是生产建筑阵列更密集，且局部运输与整厂功能仍成立。**

不得以新增独立生成模式、照搬整份增产剂图、关闭碰撞检查、只减少外围空白或只完成开关作为结项。

阶段顺序：

```text
P0 参考数据基线
    ↓
R 现有适配器普通基线与共同终检拆分
    ↔ 可并行：P1 坐标、碰撞与最小密集单元校准
    ↓
P2 数量可变的密集块与局部接驳
    ↓
P3 四种运输模式逐一接入
    ↓
P4 工作区、界面、诊断与导出闭环
    ↓
P5 密度对照、游戏验收与性能回归
```

契约、界面文案和用例可以提前准备，但不能在 P1/P2 尚未成功时宣称功能已经实现。

R 阶段先固定当前组合适配器的普通路径基线，再拆开 `finish` 的布局修改与最终检查。稳定入口、公共准备、组合注册和塔布局入口已拆出，不重复创建普通生成器包装。P2 依赖该接入边界及 P1 的几何证据。内部两种生成器都接受原有 mode，不增加公开模式号。

## 3. P1：确认真正可复用的密集单元

### 3.1 优先验证三个样本

| 样本 | 数据入口 | 首轮待验证结构 |
| --- | --- | --- |
| 化工厂密集双排 | 机器 548/518，化工厂前 6 行 | 同向双排，ΔY≈3.897/3.498，ΔX≈6.66212 |
| 制造台密集双排 | 机器 1198/1138，制造台前 4 行 | 180°/0°，ΔY≈3.400/3.045，逐行独立 ΔX |
| 熔炉密集双排 | 机器 2173/2122，熔炉四行 | 180°/0°，ΔY≈2.800/2.3168 |

三类样本均追踪原始 `Z≈0.125/0.500` 的局部带与分拣器。首先在原环境保留全部记录验证，再逐步剥离为最小可用单元。不能只留下机器、删除影响建造或运输的辅助设施后仍沿用原图证据。

### 3.2 完成坐标与规则校准

工作内容：

1. 验证所有建筑引用 Area 0、其余 Area 不直接被引用的解释，建立可重复的放置锚点。
2. 把样本转换为统一球面世界姿态，分别测量沿行、跨行与模型外形间距。
3. 对比候选阶段占位、最终静态盒、动态带、分拣器槽位及塔/电力间距。
4. 若冲突出现，保留最小复现和具体规则，不把“旧生成器不接受”等同于“游戏不允许”。
5. 检查样本是否依赖特定放置/建造顺序；实际建造完成后再确认连接仍在。
6. 对规则修正进行版本化，覆盖普通模式回归。

阶段交付：

- 三类机器的原型/模型与方向对照。
- 经验证的局部坐标变换、适用纬带、有效间距区间及数值容差。
- 机器与带/分拣器的最小闭合单元和显式外部端口。
- `PatternProfile` 实验数据与游戏验收记录。

阶段出口：至少一类生产机器的局部密集结构可在明确条件下复现；已知为何能放置，校验器与该条件一致。尚未完成的设备不伪造支持状态。

## 4. P2：从实例变成可参数化的排布能力

### 4.1 建立密度模块

建议结构，按实际职责增减：

```text
helper/blueprint/density/
  types.go          # 开关、端口、候选、报告与验证范围
  profile.go        # 规则加载、版本和能力查询
  pattern.go        # 机器对、双排、周期及余数单元
  candidate.go      # 有界候选与稳定排序
  data/             # 经验证的原型规则；保留来源与版本

helper/blueprint/build/
  generate.go, types.go    # 已有稳定入口与类型别名，保持薄层
  adapterprofile/         # 已有组合描述
  adapters/mode{1,2,3,4}/  # 已有 standard/dense/common；逐个实现 dense 能力
  contract/               # 已有塔布局/分区契约；待扩展密集块与终检数据
  shared/                 # 已有 stationlayout/zoning，共享纯规划能力
  algorithm/              # 已有私有实体装配；在此继续拆分收尾副作用
  placement/              # 已有几何占位能力
```

新子包不导入 `build`，防止循环依赖。若放置几何需要共用，先复用独立的 `placement` 能力，不让规则包访问私有 builder 或直接执行服务业务。

不再新增 generationStrategy 或两套包装；复用当前组合注册，私有 builder 转换留在 algorithm。塔模式的 Layout 目前没有密集姿态，必须同步扩展计划和实体装配，不能只改 Counts/PerGroup。密铺不直接继承 `buildLine` 的固定机器行，也不直接调用会重排机器的 `attachStations`；复用设施语义时，应抽取基于明确端口且不改变密集块的适配能力。

### 4.2 机器与局部接驳联合生成

每个候选输入：

- 可信量化产线、实际机器原型/模型、配方与机器数。
- 各物料的净流与机器毛流、供剂、回流、副产物需求。
- 所选模式的设施和端口约束。
- 带、分拣器等级及明确的科技能力。
- 球面范围与规则集版本。

每个候选输出：

- 机器姿态及局部运输/喷涂/供电记录。
- 按物品标识的真实外部端口和容量。
- 机器归属、局部建筑归属、原子组合约束。
- 相对坐标保持条件、密度指标及失败原因。

不能仅修改 `machineSpacing`。双排及余数单元需要新的机器位置、局部带、分拣器、端部接驳和供电布局。

### 4.3 数量与连接规则

- 覆盖 1 台、小于一个周期、恰好一个周期、周期数加 1、较大数量。
- 实际生产机器数严格等于可信量化机器数。
- 先建立旧引用到新 `Building.Index` 的映射，再重写所有已知连接字段。
- 数组位置、记录索引和前端 `ProductionBinding.BuildingIndices` 分开处理。
- 保留两端坐标、旋转、槽位、偏移、参数、记录布局和已知必要尾部数据。
- 提取块时逐一处理外连端口，不能把指向块外的引用全部改为 -1 后声称完整。
- 模板内边界、模板间拼接、球面转换和编码后都重新检查引用与端口独占。

### 4.4 多输入配方是独立的能力门槛

参考图的 2,113 台机器全部一进一出；配方 107/108 的多种输入通过样例的局部结构进入一条臂。跨模式推广必须至少完成：

1. 单原料、单产物的密集块。
2. 两种原料独立输入的密集块变体。
3. 喷涂与自供剂不占掉必要生产端口的变体。
4. 支持范围内的副产物和回流处理。

若某个结构只能混带，明确作为该结构的能力约束；先寻找可保留机器密度的独立输入接驳方案。需要恢复混带时，应单独完成配比、启动、饥饿/堵塞和长期吞吐验证，不能删除现有混带保护便直接放行。

阶段出口：用不同机器数和至少两种端口需求生成有效密集块。原图复制或只支持固定 73,125/min 配方链不能通过。

## 5. P3：四种模式的接入矩阵

| 公开模式 | 需要接入的位置 | 必须保留的模式行为 | 对齐状态 |
| --- | --- | --- | --- |
| 1 机器直连带 | `mode1.go`、`transport_plan.go`、`transport_router.go` | 规范物料边由实际带连接，不改成全塔运输 | 组合骨架已存在，密集几何与接驳待实现 |
| 2 物流配送器 | `fly_layout.go`、`fly_*` | 配送设施、端口与容量验证，保留原物流组织 | 组合骨架已存在，密集几何与接驳待实现 |
| 3 行星内物流塔 | `station_surround*.go`、`station_*.go` | 行星塔原型、槽位、端口、间距与本地连接 | 组合骨架已存在，密集几何与接驳待实现 |
| 4 星际物流塔 | 同塔模式入口及星际配置分支 | 星际塔设置与对应物流行为 | 组合骨架已存在，密集几何与接驳待实现 |

表中算法文件均位于 `helper/blueprint/build/algorithm/`；塔入口另见 `mode_station_pipeline.go` / `mode_station_assembly.go`，组合定义位于各 `adapters/mode*/dense`。

可先用一种模式完成纵向验证，再扩展其余模式；这是实施顺序，不改变最终四种模式均可启用的目标。

候选的选择顺序：

1. 固定机器及物料约束，枚举有限的密集局部形态。
2. 由当前模式给出块外设施与端口布局。
3. 预留真实接驳通道并执行模式外围寻路。
4. 球面转换、最终记录与功能校验。
5. 仅在成功候选中比较密度、占地和运输代价。

失败只能回溯到预算内的另一个密集候选，不静默切换运输模式、增加机器、升级运输设备或返回普通布局。

初版可以沿用当前完整生成 4 分钟的总超时；密度候选额外设置稳定的数量预算和逐阶段取消检查。具体候选数在性能基线后冻结，不以无限扩大预算解决无路问题。

阶段出口：同一类可支持的量化产线，在四种模式下分别生成保持模式语义的密集结果；不能只在直连模式成功。

### 建议错误分类

| 错误码（拟新增） | 使用条件 | 用户可理解的信息 |
| --- | --- | --- |
| `GEN_E_DENSITY_UNSUPPORTED` | 原型/模式/端口组合未覆盖 | 哪条产线、哪台设备或哪种端口需求尚不支持 |

## 7. P5：验收矩阵

### 7.1 数据与结构

- [ ] 原图严格解析与重新编码一致，源文件不被改写。
- [ ] 生成机器数、配方、等级、喷涂模式与可信计划一致。
- [ ] 模板重复和余数拼接后无悬空引用、重复索引、端口覆盖或孤立运输段。
- [ ] 已知低双层带和分拣器双端记录能够通过对应规则。
- [ ] 未识别原型、参数或不支持的变换明确拒绝。
- [ ] 单元数量改变、转向和移动后重新校验，不沿用原样例的整图白名单。

### 7.2 模式 × 密度

每种公开模式至少覆盖：

- [ ] 开关关闭，普通路径行为与基线一致。
- [ ] 开关打开，至少一组参考级机器密集结构可生成。
- [ ] 切换模式保留开关，并实际改变外围物流组织。
- [ ] 所选等级不满足要求时提示原因，绝不静默升级。
- [ ] 无可行密集结果时明确失败，不能显示普通结果为“超密度成功”。

首批三类设备需逐步覆盖四种模式。若某设备在某模式下尚未完成，支持矩阵必须标注，不能用其他设备的成功代替。

### 7.3 物料与运行

- [ ] 单输入、多输入、喷涂供剂和支持范围内回流分别验证。
- [ ] 单带和分拣器能力按实际实体与科技核算，不只看整厂总量。
- [ ] 净输出与机器毛流分开，产能不以配置数字替代真实运输覆盖。
- [ ] 物流塔和配送设施有真实端口/连接，不能只凭“设施存在”判定运输成功。
- [ ] 保留外部输入和供电边界说明，内部缺线不能交给玩家手补后仍判定生成成功。

### 7.4 密度实效

按[总体方案](超密度建筑排布总体方案.md)统一口径比较：

- [ ] 固定原型、机器数、配方、模式、等级、喷涂与放置条件。
- [ ] 机器阵列密度改善，局部功能块也可运行。
- [ ] 同时记录整厂占地、塔/箱数量、带数量、高度和总生成耗时。
- [ ] 给出同条件普通基线；基线失败就标为不可比较。
- [ ] 对参考局部单元做参考密度对照，不能只达到“比普通略密”。
- [ ] 对照使用最终记录与实际外形，不能把机器数量和带数量混算后制造密度增长。

## 9. 风险与决策依据

| 风险 | 已有依据 | 下一步决策 |
| --- | --- | --- |
| 机器密度依赖特殊低带高度 | 已测到 Y 基本重合的 Z≈0.125/0.500 两层带 | 首先验证连接与动态占位，再推广局部结构 |
| 多输入配方无法维持两臂 | 原图全部机器一进一出，多原料配方也如此 | 为独立输入设计端口变体；混带另行验证 |
| 间距无法整图使用同一常量 | 主行 ΔX 随 Y 改变，局部有补位 | 按原型和纬带参数化，保留特殊边界单元 |
| Area 解读与现有生成链不一致 | 四个 Area，但全部建筑引用 Area 0 | 先校准样例，再决定适配编码入口 |
| 原图能拍下但变体不能 | 用户确认原图可拍，变体未实测 | 每项变换按适用范围验证，不继承整图保证 |
| 高密度机器排下后运输无路 | 当前模式有独立端口、容量与外围寻路约束 | 联合枚举排布与接驳，不能只优化机器坐标 |
| 只提高统计数字 | 总建筑数被传送带主导 | 机器密度、功能块密度、整厂占地分别报告 |

这些风险决定验证顺序，不改变“任意现有模式可独立启用、核心提高建筑密度”的产品目标。


## 10. 实现进展：普通塔布局首轮改造（2026-11-03）

实际验证：`go test ./helper/blueprint/build/... -count=1 -timeout=120s` 与 `go build ./...` 通过。新增 `algorithm/layout_generation_test.go` 包含 16 个生成子用例：四模式平面铁块、两塔模式球面单机/余数/较大产线，以及电路板/处理器/精炼油多产线。生成执行原有几何、物流及编码终检；不代表游戏内可放置或吞吐已实测。

### 本轮关键修正

- `dense_reference_line.go` 使用真实来源的双端姿态、槽位、InputOffset/OutputOffset；机器数量、奇数余量、配方和所选等级在生成时参数化。端部坡道先越过机器外形再落地，插值的最后一个节点写入准确整数端口。
- `dense_reference_ports.go` 保持第三种物料独立，避免三个低层轨道的节点被游戏合并；保留机器、分拣器、附加设施、槽位与带长终检。
- 配送进料反向后，喷涂机迁到实际入口。`coater_flow.go` 沿真实有向带验证所有机器取料点都在喷涂后；普通配送的供剂端与出货干线同步延长，避免新增入口挤占箱体。
- 塔模式在接线前仅作整数格平移，避免分拣器的小数边界将本来为整数的外围端口移动到寻路不可达的位置。固定塔口段和塔中心仍检查已有占位。
- `DensityReport` 从最终候选统计参考变体覆盖并附原图 SHA-256；前端明确显示试验、单排/双排/单机或单列及预检范围。未知来源的 dense 机器不能成功返回。
