# 戴森球盒子首次使用引导教程开发指导

## 目标

基于 Driver.js、Vue 3、TypeScript、Wails、GORM 与 SQLite，实现“首次使用盒子时按页面自动展示详细引导教程”的能力。

核心要求：

- 用户第一次进入盒子时先看到全局框架引导。
- 用户第一次进入每个主页面时，根据当前页面展示对应教程。
- 教程内容要足够详细，覆盖页面主要功能、状态、入口和注意事项。
- 用户可以跳过教程。
- 教程完成或跳过后写入数据库。
- 后续进入页面时通过数据库判断，不重复弹出已完成或已跳过的教程。
- 支持后续教程版本升级，旧用户可重新看到新版教程。

## 技术选型

### 前端

- 使用 `driver.js` 本体，不使用额外 Vue wrapper。
- 使用 TypeScript 定义教程 key、步骤、版本和状态。
- 使用 Vue composable 统一控制“是否自动启动教程”。
- 使用 `data-tour` 选择器绑定页面元素，避免依赖易变化的 Tailwind class。

### 后端

- 使用 GORM 模型记录教程阅读状态。
- 使用 SQLite 本地数据库。
- 使用 Wails 服务暴露查询、完成、跳过、重置方法。
- 教程进度属于系统级用户偏好，建议放在 `model/system` 与 `service/system`。

### Driver.js 关键 API

安装与导入：

```ts
import { driver } from 'driver.js'
import 'driver.js/dist/driver.css'
```

基础用法：

```ts
const driverObj = driver({
  showProgress: true,
  nextBtnText: '下一步',
  prevBtnText: '上一步',
  doneBtnText: '完成',
  progressText: '{{current}} / {{total}}',
  steps: [
    {
      element: '[data-tour="main-nav"]',
      popover: {
        title: '主导航',
        description: '这里是盒子的主要功能入口。',
        side: 'right',
        align: 'start',
      },
    },
  ],
  onCloseClick: () => {
    driverObj.destroy()
  },
  onDoneClick: () => {
    driverObj.destroy()
  },
})

driverObj.drive()
```

注意：如果配置了 `onCloseClick` 或 `onDoneClick`，回调里要手动调用 `destroy()`；如果自定义 `onNextClick`、`onPrevClick`，也要手动调用 `moveNext()`、`movePrevious()`。

## 数据库设计

### 新增模型文件

建议新增：

- `model/system/tutorial_progress.go`
- 更新 `model/system/enter.go`

表名建议：`system_tutorial_progresses`

字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uint64 | 主键 |
| `page_key` | string | 教程页面 key，如 `global`、`mod` |
| `tutorial_version` | int | 教程版本 |
| `status` | string | `completed` 或 `skipped` |
| `completed_at` | `*time.Time` | 完成时间 |
| `skipped_at` | `*time.Time` | 跳过时间 |
| `created_at` | `time.Time` | 创建时间 |
| `updated_at` | `time.Time` | 更新时间 |

唯一索引：

- `page_key + tutorial_version`

原因：

- 同一页面同一版本只需要一条状态记录。
- 后续教程内容改动时提升版本号，旧记录不会阻止新版教程展示。

### 状态枚举

建议新增常量文件：

- `constant/system/tutorial.go`

常量：

- `TutorialStatusCompleted = "completed"`
- `TutorialStatusSkipped = "skipped"`

## 后端服务设计

### 新增服务文件

建议新增：

- `service/system/tutorial.go`
- 更新 `service/system/enter.go`

服务结构体：

```go
type TutorialService struct{}
```

建议暴露给前端的方法：

| 方法 | 用途 |
| --- | --- |
| `GetTutorialProgress(pageKey string, tutorialVersion int)` | 查询某页某版本教程状态 |
| `MarkTutorialCompleted(pageKey string, tutorialVersion int)` | 标记完成 |
| `SkipTutorial(pageKey string, tutorialVersion int)` | 标记跳过 |
| `ResetTutorialProgress(pageKey string)` | 重置单页或全部教程 |

### DTO 设计

建议在 `service/system/tutorial.go` 或 `service/system/dto.go` 中定义：

```go
type TutorialProgressDTO struct {
	PageKey         string `json:"pageKey"`
	TutorialVersion int    `json:"tutorialVersion"`
	Status          string `json:"status"`
	Completed       bool   `json:"completed"`
	Skipped         bool   `json:"skipped"`
}
```

前端判断逻辑：

- `completed === true`：不自动展示。
- `skipped === true`：不自动展示。
- 没有记录或记录版本不匹配：自动展示。

### 后端校验规则

服务层需要校验：

- `pageKey` 不能为空。
- `tutorialVersion` 必须大于 0。
- `status` 只能是 `completed` 或 `skipped`。

写入策略：

- 完成与跳过都使用 upsert 语义。
- 同一 `pageKey + tutorialVersion` 已存在时更新 `status` 与对应时间字段。
- 完成时清空或保留 `skipped_at` 均可，推荐完成时将 `skipped_at` 置空，语义更清晰。

### 生成 Wails 绑定

新增或修改 Wails 暴露方法后，在项目根目录执行：

```powershell
go build ./...
wails generate module
```

生成后前端会出现：

- `frontend/wailsjs/go/system/TutorialService.ts`

不要手动编辑 `frontend/wailsjs`。

建议新增：

frontend/src/tutorials/

frontend/src/composables/

### `types.ts`

职责：

- 定义教程页面 key。
- 定义教程配置。
- 定义页面教程状态。

建议类型：

```ts
export type TutorialPageKey =
  | 'global'
  | 'home'
  | 'headless'
  | 'mod'
  | 'blueprint'
  | 'environment'
  | 'log'
  | 'settings'
  | 'about'

export interface TutorialDefinition {
  readonly pageKey: TutorialPageKey
  readonly version: number
  readonly autoStart: boolean
  readonly steps: readonly TutorialStep[]
}

export interface TutorialStep {
  readonly selector?: string
  readonly title: string
  readonly description: string
  readonly side?: 'top' | 'right' | 'bottom' | 'left'
  readonly align?: 'start' | 'center' | 'end'
}
```

### `selectors.ts`

职责：

- 集中维护所有 `data-tour` 名称。
- 避免页面字符串散落。

示例：

```ts
export const TOUR_SELECTORS = {
  mainNav: '[data-tour="main-nav"]',
  headerTitle: '[data-tour="header-title"]',
  themeToggle: '[data-tour="theme-toggle"]',
  modSearch: '[data-tour="mod-search"]',
} as const
```

### `registry.ts`

职责：

- 按页面注册教程版本和步骤。
- 不调用 Wails，不直接启动 Driver.js。

建议结构：

```ts
export const tutorialRegistry: Record<TutorialPageKey, TutorialDefinition> = {
  global: {
    pageKey: 'global',
    version: 1,
    autoStart: true,
    steps: [
      {
        selector: TOUR_SELECTORS.mainNav,
        title: '主导航',
        description: '这里集中进入首页、开服、模组、蓝图、资源、日志、设置和关于我们。',
        side: 'right',
        align: 'start',
      },
    ],
  },
}
```

### `usePageTutorial.ts`

职责：

- 页面挂载或激活时查询后端状态。
- 如果未完成且未跳过，等待 DOM 渲染后启动 Driver.js。
- 完成或跳过时写回数据库。
- 路由切换或组件卸载时销毁 Driver.js。

建议能力：

- `startTutorial(pageKey, options?)`
- `restartTutorial(pageKey)`
- `shouldAutoStartTutorial(pageKey)`
- `destroyTutorial()`

关键流程：

```text
1. 根据 pageKey 读取 registry 定义。
2. 调用 TutorialService.GetTutorialProgress(pageKey, version)。
3. 如果 completed/skipped 为 true，停止。
4. 等待 nextTick 和短延迟，确保目标元素渲染。
5. 过滤当前页面不存在的 selector。
6. 创建 driver 实例并 drive。
7. onCloseClick 写入 SkipTutorial。
8. onDoneClick 写入 MarkTutorialCompleted。
9. 页面卸载、路由切换时 destroy。
```

目标元素缺失策略：

- 如果某一步 selector 不存在，跳过该步。
- 如果所有步骤都不存在，不启动教程，也不写完成状态。
- 控制台可 `console.warn` 输出缺失 selector，便于开发检查。

### `TutorialLauncher.vue`

用途：

- 给用户一个“重新查看本页教程”的入口。
- 推荐放在顶部标题栏或页面右上角，不强制每页单独写按钮。

交互：

- 点击后忽略数据库状态，直接启动当前页教程。
- 不改变旧状态，只有用户完成或跳过后再覆盖记录。

## 页面元素标记规范

所有被引导的目标元素都加 `data-tour`：

```vue
<nav data-tour="main-nav">
  ...
</nav>
```

命名规则：

- 使用 kebab-case。
- 以页面或模块开头，避免冲突。
- 示例：`mod-search`、`headless-start`、`settings-game-path`。

不推荐：

- 使用 Tailwind class 作为 selector。
- 使用自动生成的 Naive UI 内部 class。
- 使用复杂的 `nth-child`。

## 自动启动时机

推荐顺序：

1. `App.vue` 或 `MainLayout.vue` 初始化时加载主题等基础状态。
2. 当前路由页面挂载后，页面调用 `usePageTutorial(pageKey)`。
3. composable 查询后端状态。
4. `nextTick()` 后再延迟 100 到 200ms，等待 Naive UI、数据加载遮罩、异步列表渲染。
5. 如果目标 selector 存在，启动 Driver.js。

对于数据异步页面：

- `headless`、`mod`、`environment`、`log` 可能首次渲染时没有完整数据。
- 教程目标尽量绑定到固定容器、工具栏、空态和遮罩，而不是绑定到某条动态数据。
- 例如模组页绑定 `mod-package-grid`，不要绑定第一张实际整合包卡片。

## 跳过与完成语义

| 用户行为 | 后端状态 | 后续是否自动展示 |
| --- | --- | --- |
| 点击关闭按钮 | `skipped` | 否 |
| 点击最后一步完成 | `completed` | 否 |
| 手动重新查看并关闭 | `skipped` | 否 |
| 手动重新查看并完成 | `completed` | 否 |
| 教程版本提升 | 无新版记录 | 是 |

推荐文案：

## 开发顺序建议

优先顺序：

1. 后端模型和服务。
2. Wails 绑定生成。
3. 前端教程基础模块。
4. 全局教程。
5. 设置页教程。
6. 模组页教程。
7. 开服页教程。
8. 资源页教程。
9. 日志、蓝图、关于、首页教程。
10. 重看入口与样式打磨。

原因：

- 设置页是其他页面的前置配置入口，应优先打通。
- 模组和开服依赖游戏路径和 BepInEx 状态，教程价值最高。
- 资源页交互最多，建议在基础链路稳定后再做。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| 页面数据未加载，selector 不存在 | 过滤缺失步骤，绑定固定容器而不是动态列表项 |
| 用户快速切换路由，遮罩残留 | composable 在 `onBeforeUnmount` / `onDeactivated` 中 `destroy()` |
| 教程已跳过但新版需要展示 | 使用 `tutorialVersion` 控制 |
| 后端绑定未生成 | 修改服务后必须执行 `wails generate module` |
| Naive UI 弹窗内元素难定位 | 对弹窗外层或打开按钮做教程，避免强依赖内部 DOM |
| 暗色模式不适配 | 在 `style.scss` 中按 `:root[data-theme='dark']` 覆盖 Driver.js 主题 |
